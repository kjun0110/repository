# 온톨로지 설계 원칙의 중요성
- 기반이 흔들리면 위가흔들림
	- 잘못 설계한 온톨로지 위에 올린 llm agent는 같이 불안정해짐
- 부실 설계의 비용이 자동으로 증폭됨
	- 자율적 에이전트 일수록 틀린 전제가 검토없이 행동으로 번짐
- 잘 정의된 온톨로지 = 의미 제어 계층
	- 환각, 잘못된 툴 사용, 정책 위반을 걸러주는 가드레일
- 그렇다면 잘 설계됐다는 것을 무엇으로 판단하는가?
	- Gruber 5원칙 (명확성, 정합성, 확장성, 최소 인코딩 편항, 최소 개입)

# 지식 공유와 재사용을 위해 
- Gruber(1995) = 온톨로지를 "잘 설계"하는 법
	- 어떻게 설계, 의미와 논리의 품질 -> 설계 5원칙
- FAIR(2020) = 설계된 온톨로지를 웹에서 "잘 공개, 운영"하는법
	- 설계된 온톨로지를 웹에서 어떻게 찾고 접근 재사용?, 공개와 재사용가능성 -> URI, 문서, 버전, 메타데이터, 등록가이드 

# Gruber(1995) 논문 - 설계원칙제안
#Toward_Principles_for_the_Design_of_Ontologies_Used_for_Knowlege_Sharing
- 온톨로지는 지식공유라는 목적을 위해 사람이 만드는 설계물 -> 목적에 맞게 잘 만들었는가 로 평가
- 온톨로지 = conceptualization을 명시적으로 적어둔 것
- 즉 누구나 똑같이 읽도록 공통 용어와 규칙을 분명이 써놓은 것 
- 지식을 공유하려면 용어를 같은 뜻으로 쓰자는 합의가 필요 - 온톨로지는 합의를 문서로 분명이 적어두는 역할

Ontology Commitment
	온톨로지 = 머릿속 모델(conceptualization)을 누구나 읽도록 적어둔것
- 구성 - 용어목록 + 각 용어의 뜻을 제한하는 규칙(axiom) + 사람이 읽을 자연어 설명
- Ontological commitment - 용어들을 같은 뜻으로 일관되게 쓰자는 약속 

온톨로지 설계 5원칙
- 명확성(Clarity)
	- 용어의 뜻이 누구에게나 똑같이 분명히 전달
	- LLM이 용어를 과하게 추론하지 않도록, 구체적 이름, 정의 ,형식, 제약, 예시, 반례를 함께 제공
- 정합성(Cogerence)
	- 도출된 결론이 정의와 모순되면 안됨
	- KG가 잘못된 추론을 하지 않도록 방지, llm이 자동 생성한 온톨로지kg의 검증기준
- 확장성(Extendibility)
	- 기존 정의는 그대로 두고 그 위에 덧붙여 확장 가능
	- 거대 온톨로지를 한번에 만들지 않고 핵심부분부터 작게 시작해 모듈로 확장(골든 데이터부터)
- 최소 인코딩 편향(Minimal encoding bias)
	- 특정 구현, 표기 방식에 의존하지 않고 정의
	- 표준 형식으로 작성 - 특정 벤터 툴에 종속되지 않고 시스템간 그대로 주고받음
- 최소 존재론적 개입(Minimal ontological commitment)
	- 꼭 필요한 것만 정의하고 불필요한 제약은 두지 않음
	- 필요 이상으로 과설계 하면 유지, 확장이 어려움
	- 쓸 만큼만 정의하는것이 llm 자동 구축의 핵심

원칙 간 Tradeoff - 모순돼 보이지만 아님
- 명확성(정의하기로 한 용어를 명확히 적어라)
- 최소 존재론적 개입(용어를 몇개나 정의할지)
- 확장성(확장 가능한 구조)
- 최소개입(미리 넣지 마라)

	- uri끝을 #(작음), /(큼) 중 뭘로 할지 정함
	- URI 안전관리
		- Opaque URI(wikidata) - 바뀌어도 중립적 - 대신 읽기위한 도구 필요
		- Permanent URI - 
	- uri에 버전을 넣으면 안됨 - 버전은 별도 속성으로 
- 문서화(Sec 3) - 남이 이해하게 메타데이터, 분서, 다이어그램 어떻게 만드는가?
	- 메타 데이터 (온톨로지, 용어)
		- 무엇, 누가 만들었고 어떻게 써도 되는지 적혀야 함
		- 뜻 출처 사용조건 등 명확하게
	- 문서 & 다이어그램 (다이어그램은 표준 표기법은 없음 -)
		- HTML문서 자동생성으로 사람도 읽을 수 있도록 제안 
		- 이에 대허 동기, 맥락, 요구사항, 사용예시, 다이어그램 덧붙이길 권장
- Web공개(Sec 4) - 사람 기계 모두 접근 검색하게 어떻게 올릴지?
	- 접근성
		- 브라운저로 열면 HTML
		- 에디터로 열면 RDF seialization 으로 나오게 함
	- 검색성
		- prefix.cc에 등록
		- 메타데이터 등록서에 등록
		- HTML문서에 JSON-LD 주석을 심어 검색 크롤러가 메타데이터를 읽을 수 있도록 함
- 통합 프레임 워크(Sec 5) - 위과정 한번에 도와주는 도구?
	- 문서화, 시각화, 평가, 테스트, 공개를 하나로 묶어줌
	- Ontoology, Vocol, pool party
