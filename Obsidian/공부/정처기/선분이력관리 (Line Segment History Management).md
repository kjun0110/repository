## 개념

데이터의 변경 이력을 **시작일자 ~ 종료일자** 형태의 유효 기간(선분)으로 관리하는 방식입니다.
단순히 최신 데이터만 저장하는 것이 아니라, **언제부터 언제까지 어떤 값이었는지**를 모두 보존합니다.

---

## 기본 구조

| 사원번호 | 부서 | 시작일자 | 종료일자 |
|----------|------|----------|----------|
| 1001 | 개발팀 | 2022-01-01 | 2023-06-30 |
| 1001 | 기획팀 | 2023-07-01 | 2024-12-31 |
| 1001 | 개발팀 | 2025-01-01 | 9999-12-31 |

- 종료일자가 `9999-12-31`이면 **현재 유효한 데이터**를 의미

---

## 핵심 원칙

- **선분 연속성**: 동일 키의 시작일~종료일 구간이 끊기지 않고 이어져야 함
- **선분 중복 금지**: 동일 키의 유효 기간이 겹쳐서는 안 됨
- **현재 종료일 = 9999-12-31**: 아직 끝나지 않은 최신 데이터의 관례적 표현

---

## 주요 조회 패턴

### 현재 유효 데이터 조회
```sql
SELECT * FROM 사원이력
WHERE 사원번호 = 1001
  AND 종료일자 = '9999-12-31';
```

### 특정 시점 데이터 조회 (Point-in-Time)
```sql
SELECT * FROM 사원이력
WHERE 사원번호 = 1001
  AND '2023-10-01' BETWEEN 시작일자 AND 종료일자;
```

---

## 선분 변경 처리 (이력 추가 시)

새로운 값으로 변경할 때는 기존 선분을 닫고 새 선분을 추가합니다.

```
변경 전:
[2025-01-01 ~ 9999-12-31] 개발팀

변경 후 (2025-08-01부터 기획팀으로 이동):
[2025-01-01 ~ 2025-07-31] 개발팀   ← 종료일자 업데이트
[2025-08-01 ~ 9999-12-31] 기획팀   ← 신규 행 삽입
```

---

## 장단점

| | 내용 |
|--|------|
| **장점** | 과거 임의 시점 데이터 조회 가능, 감사/이력 추적 용이 |
| **단점** | 테이블 row 수 증가, 쿼리 복잡도 상승, 선분 무결성 관리 필요 |

---

## 활용 사례

- 인사 시스템: 직급, 부서, 급여 변경 이력
- 금융 시스템: 금리, 한도 변경 이력
- 상품/가격 관리: 가격 변동 이력

---

## 한 눈에 요약

```
선분이력    →  시작일자 ~ 종료일자로 유효 기간을 관리
9999-12-31  →  현재 유효한 데이터
변경 처리   →  기존 선분 종료일 업데이트 + 새 선분 삽입
조회        →  특정 날짜 BETWEEN 시작일자 AND 종료일자
```
