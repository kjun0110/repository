## 개념

네트워크 통신을 **7단계로 나눠 표준화**한 모델입니다.
각 계층은 독립적인 역할을 수행하며, "naver.com을 브라우저에 입력했을 때" 실제로 어떤 일이 일어나는지로 이해할 수 있습니다.

## 전체 구조

```
[ 사용자 ]
    ↕
7계층  응용 계층      (Application)   HTTP, FTP, DNS
6계층  표현 계층      (Presentation)  SSL/TLS, 암호화
5계층  세션 계층      (Session)       세션 연결/종료
4계층  전송 계층      (Transport)     TCP, UDP
3계층  네트워크 계층  (Network)       IP, 라우터
2계층  데이터링크 계층(Data Link)     MAC, 스위치
1계층  물리 계층      (Physical)      케이블, 전기신호
    ↕
[ 네트워크 ]
```

---

# 계층별 상세 설명

## L7 — 응용 계층 (Application)

**"무슨 요청인지 결정"**

브라우저가 이렇게 말합니다:
```
GET / HTTP/1.1
Host: naver.com
```
사람이 직접 보는 레벨. 어떤 서비스를 어떻게 요청할지 결정하는 곳입니다.

- 대표 프로토콜: HTTP, HTTPS, FTP, DNS, SMTP

## L6 — 표현 계층 (Presentation)

**"암호화/복호화"**

HTTPS라면 데이터를 암호화합니다.
```
"naver.com 줘" → [암호화] → #@$%^&*(암호문)
```
상대방이 못 알아보게 포장하는 곳. SSL/TLS가 여기서 동작합니다.

- 대표 기술: SSL/TLS, JPEG, UTF-8

## L5 — 세션 계층 (Session)

**"연결 유지 관리"**

로그인 상태를 유지하거나, 연결이 끊겼을 때 재연결하는 역할을 합니다.
```
"이 대화는 세션 ID #1234야, 끊기면 다시 연결해"
```
전화 통화로 치면 "통화 연결 유지" 담당입니다.

- 대표 기술: NetBIOS, RPC

## L4 — 전송 계층 (Transport)

**"어떤 앱으로 보낼지 + 잘 도착했는지 확인"**

포트 번호로 앱을 구분합니다:
```
80번 포트   → 웹서버 (HTTP)
443번 포트  → HTTPS 웹서버
3306번 포트 → MySQL
```
- `TCP` — "잘 받았어?" 확인하며 신뢰성 있게 전송
- `UDP` — 확인 없이 빠르게 전송 (스트리밍, 게임)

아파트로 치면 "몇 동 몇 호"까지 찾아가는 것입니다.

## L3 — 네트워크 계층 (Network)

**"목적지까지 경로 탐색"**

IP 주소로 naver 서버가 어디 있는지 찾아갑니다.
```
내 IP:    192.168.0.10
naver IP: 223.130.195.200

서울 → 부산 가려면 어떤 길로? (라우터들이 결정)
```
네비게이션 역할이며, 라우터가 이 계층에서 동작합니다.

- 대표 프로토콜: IP, ICMP

## L2 — 데이터링크 계층 (Data Link)

**"같은 네트워크 안에서 옆집 찾기"**

```
IP  = 서울시 강남구 (넓은 주소)
MAC = 실제 건물 고유번호
```
같은 공유기에 연결된 장비들 사이에서 실제 전달을 담당합니다.
스위치가 이 계층에서 동작합니다.

- 대표 기술: Ethernet, MAC 주소

## L1 — 물리 계층 (Physical)

**"실제 전기신호로 전송"**

데이터를 0과 1로 바꿔서 케이블/와이파이로 쏩니다.
```
데이터 → 01001000 → 전기신호 ~~~~~
```
내용은 모르고 그냥 신호만 전달합니다. 케이블, 공유기 포트가 여기에 해당합니다.

# 실무 활용

## 자주 듣는 표현

| 표현 | 의미 |
|------|------|
| **L4 로드밸런서** | IP/포트 기준으로 트래픽 분산, 하드웨어 장비 |
| **L7 로드밸런서** | URL/헤더 기준으로 트래픽 분산, 소프트웨어(Nginx 등) |
| **L3 스위치** | IP 라우팅이 가능한 스위치 |
| **방화벽** | L3~L7 계층에서 패킷 필터링 |

## L4 vs L7 로드밸런서 비교

| | L4 | L7 |
|--|----|----|
| **기준** | IP/포트 | HTTP 헤더, URL, 쿠키 |
| **구현** | 하드웨어 장비 | 소프트웨어 (Nginx 등) |
| **성능** | 빠름 | 상대적으로 느림 |
| **기능** | 단순 분산 | 정교한 라우팅 가능 |
| **비용** | 장비값 비쌈 | 무료(오픈소스) |

## 한 눈에 요약

```
L7  무슨 요청이야?
L6  암호화할게
L5  연결 유지할게
L4  몇 번 포트야? 잘 받았어?
L3  어디로 가야 해? (IP/경로)
L2  같은 네트워크 안에서 누구야? (MAC)
L1  전기신호로 쏜다
```
