## 개념

**RAG 평가**는 검색(Retrieval)과 생성(Generation) 두 단계를 분리해서 측정한다. 검색은 "질문에 맞는 정보를 잘 찾아왔는가", 생성은 "찾아온 정보로 만든 답변이 정확하고 적절한가"를 각각 0~1 사이 값으로 정량화한다. 두 단계를 합쳐서 하나의 점수로 보면 어디가 문제인지(검색이 못 찾은 건지, LLM이 잘못 합성한 건지) 구분이 안 되기 때문에 반드시 나눠서 본다.

---

## 검색(Retrieval) 지표

### Hit Rate

상위 K개 검색 결과 안에 정답 문서가 있는지 여부(1 또는 0)를 질문 전체에 대해 평균낸 값.

```
HitRate@K = (정답이 top-K 안에 있었던 질문 수) / (전체 질문 수)
```

가장 단순하고 직관적인 지표. 단, "정답이 있냐 없냐"만 보고 **몇 등으로 찾았는지는 반영 안 함**.

### MRR (Mean Reciprocal Rank)

첫 번째 정답이 몇 등으로 검색됐는지의 역수를 평균낸 값. 정답이 상위에 있을수록 1에 가까움.

```
질문 A: 정답이 1위  → 1/1   = 1.0
질문 B: 정답이 2위  → 1/2   = 0.5
질문 C: 정답이 3위  → 1/3   = 0.33
질문 D: 정답이 없음 → 0

MRR = (1.0 + 0.5 + 0.33 + 0) / 4 = 0.46
```

Hit Rate가 "찾았다/못 찾았다"만 본다면, MRR은 **"찾긴 했는데 순위가 밀렸는지"**까지 구분한다. 정답이 2~3위로 밀려서 다른 오답이 1위를 차지하는 실패 패턴을 잡아낼 때 유용하다.

### nDCG (Normalized Discounted Cumulative Gain)

검색 결과 여러 개에 **등급별 관련도**(예: 0=무관, 1=약간 관련, 2=매우 관련)가 있을 때, 관련도 높은 문서가 상위에 있는지를 종합 평가하는 지표.

```
DCG  = Σ (관련도_i / log2(순위_i + 1))
nDCG = DCG / IDCG   (IDCG = 이상적인 순서로 정렬했을 때의 DCG)
```

질문당 **여러 개의 유의미한 문서**가 있고 그 중요도가 제각각인 태스크(예: 일반 문서 검색)에 적합하다. 반대로 질문당 정답이 하나뿐인 태스크에서는 등급 자체가 없어 의미가 약해진다.

### Context Precision

검색된 결과 중 실제로 답변에 필요한 정보가 **상위에 몰려 있는지**를 평가. 관련 있는 문서가 앞쪽에 있으면 높은 점수, 뒤섞여 있거나 무관한 내용이 앞에 있으면 낮은 점수.

### Context Recall

정답을 만드는 데 필요한 정보 **전체**가 검색 결과에 빠짐없이 포함됐는지 평가. Precision이 "가져온 것 중 얼마나 맞았나"라면, Recall은 "맞혀야 할 것 중 얼마나 가져왔나".

```
Precision = 검색결과 중 관련 있는 것 / 검색결과 전체
Recall    = 검색결과 중 관련 있는 것 / 정답에 필요한 전체 정보
```

한 질문에 필요한 정보가 여러 조각(예: 필요서류 + 법적 근거 + 처리 절차)으로 나뉘어 있을 때, 그 중 일부만 가져오고 나머지를 놓치는 상황을 Recall이 잡아낸다.

## 생성(Generation) 지표

### Faithfulness (충실도)

생성된 답변이 **검색된 컨텍스트에만 근거하는지** 측정. 답변을 문장 단위(claim)로 쪼개서 각 claim이 컨텍스트로부터 추론 가능한지 LLM으로 판정하고, 그 비율을 점수로 낸다.

```
Faithfulness = (컨텍스트로 뒷받침되는 claim 수) / (답변 전체 claim 수)
```

컨텍스트에 없는 내용을 답변이 지어내면(환각, Hallucination) 이 점수가 떨어진다. 검색은 잘했는데 LLM이 엉뚱한 소리를 보탰는지를 걸러내는 지표.

### Answer Relevance (답변 관련성)

답변이 **원래 질문의 의도**에 맞는 내용을 담고 있는지 측정. 흔한 구현 방식은 답변으로부터 역으로 예상 질문을 여러 개 생성한 뒤, 그 질문들과 원래 질문의 임베딩 유사도를 평균내는 것.

정확한 사실이어도 질문과 동떨어진 내용이면(예: 딴 이야기를 정확하게 하는 경우) 이 점수는 낮게 나온다 — Faithfulness와는 독립적인 축.

### Semantic Similarity (의미적 유사도)

미리 준비한 모범 답안(Ground Truth)과 생성된 답변을 임베딩으로 변환해 코사인 유사도로 비교. 문장 표현이 달라도 의미가 같으면 높은 점수.

```
similarity = cosine(embed(생성답변), embed(모범답안))
```

open-ended 서술형 답변 평가에 적합. 다만 "표현은 비슷한데 사실은 틀린" 답변도 유사도가 높게 나올 수 있어, 사실 정확성 검증 목적으로는 Faithfulness를 대체하지 못한다.

## 태스크 형태에 따른 지표 적합성

모든 지표가 모든 RAG 시스템에 똑같이 유용하지는 않다. 특히 "질문당 정답 문서가 하나"인 태스크(예: 담당 부서 찾기)와 "질문당 관련 문서가 여러 개, 중요도도 제각각"인 태스크(예: 일반 문서 검색)는 잘 맞는 지표가 다르다.

| 지표 | 정답이 1개뿐인 태스크 | 관련 문서가 여러 개·등급별인 태스크 |
|---|---|---|
| Hit Rate | 적합 | 적합 |
| MRR | 적합 (순위 밀림 진단에 유용) | 적합 |
| nDCG | 부적합 (등급 자체가 없음) | **적합** |
| Context Precision/Recall | 답변에 필요한 정보가 여러 조각일 때만 의미 있음 | 적합 |
| Semantic Similarity | Ground Truth가 짧은 고정값이면 부적합 | 서술형 답변일 때 적합 |
| Faithfulness | 항상 적합 (사실 기반 도메인일수록 우선순위 높음) | 항상 적합 |

## 실전 적용 판단 — suwon_ontology_opus 기준

"정답이 1개뿐인 태스크"의 실제 사례로, 수원시 조직도 그래프RAG 프로젝트에 대입한 판단.

### 검색 지표

| 지표 | 적용 판단 | 이유 |
|---|---|---|
| Hit Rate | ✅ 이미 쓰고 있음 | `eval/run_eval.py`의 "36문항 Top-1 정확도(97%)"가 사실상 Hit Rate@1. `@3`, `@5`로 확장하면 더 세밀해짐 |
| MRR | ✅ 바로 도입 가치 큼 | 남은 실패 사례(X03 "가로등 고장"→`가로수팀`)가 딱 MRR 문제 — 정답(`안전건설과`)이 아예 없는 게 아니라 순위가 밀린 케이스일 수 있음. Top-1만 보면 이런 "근처까지 갔는데 놓친" 걸 못 잡아냄 |
| nDCG | ⚠️ 적용 가치 낮음 | 질문당 "정답 부서 1개"라 등급 자체가 없음. 지금 태스크 형태와 안 맞음 |
| Context Precision | ⚠️ 지금은 낮음, Layer 2 이후 중요 | Layer 1(조직 검색)만 있는 지금은 컨텍스트가 단순함. Layer 2에서 멀티홉으로 서류·법령·연락처를 끌어올 때부터 "끌어온 것 중 진짜 필요한 게 얼마나 되냐"가 의미 생김 — "무제한 홉은 노이즈" 문제를 정량화하는 지표 |
| Context Recall | ⚠️ Layer 2 이후 중요 | "필요서류+법령+절차 3가지를 다 가져왔나"처럼 여러 조각이 필요한 답변에서 의미 생김. 지금(단일 부서 조회)은 recall≈precision이라 따로 잴 이유가 적음 |

### 생성 지표

| 지표 | 적용 판단 | 이유 |
|---|---|---|
| Faithfulness | ✅✅ 최우선 도입 추천 | 민원 도메인이라 환각이 실제 피해로 이어짐(틀린 서류 안내 등). "그래프에 박힌 사실만 답하기"가 이미 설계 원칙인데 지금은 사람 눈으로만 검증 중 — 정량 지표화할 가치 큼 |
| Answer Relevance | 🟡 보통 | 지금은 "정답 부서 이름 맞았나"로 사실상 커버되고 있음. Layer 2에서 서술형 답변(절차 설명 등)이 늘어나면 그때 가치가 올라감 |
| Semantic Similarity | ❌ 적용 가치 낮음 | Ground Truth가 "부서명/태그" 같은 명확한 값이라 텍스트 유사도로 잴 이유가 없음. "비슷하지만 틀린 법령 조항"을 유사도가 높다고 통과시키는 위험이 있어 이 도메인엔 안 맞음 |

## 한 눈에 요약

```
검색(Retrieval) 지표
  Hit Rate        →  top-K 안에 정답이 있었나 (1/0)
  MRR             →  정답이 몇 등이었나 (순위 밀림 진단)
  nDCG            →  등급별 관련도까지 반영한 순위 품질 (다중 정답 태스크용)
  Context Precision →  가져온 것 중 관련 있는 게 상위에 몰려있나
  Context Recall  →  답변에 필요한 정보를 빠짐없이 가져왔나

생성(Generation) 지표
  Faithfulness    →  답변이 컨텍스트 안에서만 나왔나 (환각 방지)
  Answer Relevance →  답변이 질문 의도에 맞나
  Semantic Similarity →  모범답안과 의미가 비슷한가

지표 선택 기준
  →  정답이 1개뿐인 태스크: Hit Rate·MRR·Faithfulness 우선
  →  관련 문서가 여러 개·등급별인 태스크: nDCG·Context Precision/Recall 추가
  →  사실 기반 도메인(환각 시 실피해 발생): Faithfulness 최우선

suwon_ontology_opus 적용 우선순위
  1순위 Faithfulness  →  민원 도메인, 환각이 실피해로 연결
  2순위 MRR           →  기존 eval에 한 줄 추가로 순위 밀림 진단 가능
  3순위 Hit Rate@K    →  기존 Top-1 지표의 자연스러운 확장
  보류  Context P/R    →  Layer 2(멀티홉) 구현 시점에 같이 도입
  비적용 nDCG·Semantic Similarity →  정답 1개뿐인 태스크 형태와 안 맞음
```
