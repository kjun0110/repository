## 개념

텍스트를 검색 및 처리에 적합한 크기로 **분할하는 방법**입니다.공부
RAG 파이프라인에서 문서를 어떻게 나누느냐에 따라 검색 품질이 크게 달라집니다.

---

# 청킹 방식 종류

## 1. 고정 크기 청킹 (Fixed-size Chunking)

의미와 상관없이 토큰이나 글자 수를 기준으로 500자, 1000자씩 일정하게 텍스트를 분할하는 **가장 단순한 방식**입니다.

- 구현이 쉽고 빠름
- 문장이나 문단 경계를 무시하므로 의미가 잘릴 수 있음

## 2. 재귀적 청킹 (Recursive Chunking)

줄 바꿈, 문단, 마침표, 공백 등 **기정의된 구분자 목록을 순차적으로 탐색**하며 지정된 크기에 맞춰 유연하게 텍스트를 자르는 방식입니다.

- LangChain의 `RecursiveCharacterTextSplitter`가 대표적
- 고정 크기 청킹보다 자연스러운 분할 가능

## 3. 의미론적 청킹 (Semantic Chunking)

고정된 크기 대신 **문장 간의 임베딩 유사도를 계산**하여 문맥이 급격하게 변하는 지점을 기준으로 텍스트를 나누는 방식입니다.

- 의미 단위로 분할되어 검색 품질이 높음
- 임베딩 모델이 필요하므로 처리 비용이 상대적으로 높음

## 4. 계층적 청킹 (Hierarchical / Parent-Child Chunking)

데이터를 **큰 덩어리(상위 청크)** 와 **세부 덩어리(하위 청크)** 의 중첩 구조로 구성하여, 요약 정보와 상세 정보를 동시에 활용하는 기법입니다.

- 검색 시 하위 청크로 정밀 탐색, 상위 청크로 맥락 제공
- RAG 파이프라인에서 정확도와 문맥 유지를 동시에 달성

## 5. 후기 청킹 (Late Chunking)

문서 전체를 먼저 임베딩 처리한 뒤, **전체적인 컨텍스트 손실을 최소화**하면서 필요한 청크 경계로 분할하는 고도화된 방식입니다.

- 청크 분리 전에 전체 문서의 문맥을 임베딩에 반영
- 초기 청킹 방식들보다 정보 손실이 적음

# 오버랩 (Overlap)

청킹 시 **인접한 청크끼리 일부 텍스트를 겹치게** 하여 경계에서 문맥이 끊기는 것을 방지하는 기법입니다.
청킹 방식과 별개로 대부분의 청킹에 함께 적용됩니다.

## 오버랩 없을 때 vs 적용 시

```
[오버랩 없음]
[청크1] ...RAG는 검색과 생성을 결합한 방식이다. 이 방식은
[청크2] 외부 지식을 활용하여 답변을 생성한다...
→ 청크2만 검색되면 "이 방식"이 뭔지 알 수 없음

[오버랩 적용]
[청크1] ...RAG는 검색과 생성을 결합한 방식이다. 이 방식은
[청크2] 이 방식은 외부 지식을 활용하여 답변을 생성한다...
           ^^^^^^^^ 겹치는 구간
→ 청크2에도 앞 문맥이 포함되어 의미 단절 방지
```

## 핵심 파라미터

| 파라미터 | 역할 |
|----------|------|
| `chunk_size` | 청크 하나의 최대 크기 |
| `chunk_overlap` | 앞 청크와 겹치는 크기 |

- 오버랩 **크게** → 문맥 보존 좋음, 중복 데이터 증가, 비용 상승
- 오버랩 **작게** → 효율적, 경계 문맥 손실 위험
- 보통 청크 크기의 **10~20%** 를 오버랩으로 설정하는 것이 일반적

---

## 한 눈에 요약

```
고정 크기   →  글자/토큰 수 기준, 구현 단순, 의미 단절 가능
재귀적      →  구분자 목록 탐색, 자연스러운 분할
의미론적    →  임베딩 유사도 기준, 문맥 보존 우수, 비용 높음
계층적      →  상위/하위 구조, 맥락 + 정밀도
후기        →  전체 임베딩 후 분할, 컨텍스트 손실 최소

오버랩      →  인접 청크 일부 겹치기, 경계 문맥 단절 방지
```
