# 공부 폴더 작성 규칙

---

## 파일명 규칙

- **한글명 (영문명)** 풀네임으로 작성 (예: `청킹 종류 (Chunking Types).md`)
- 파일명이 곧 제목이므로 H1은 파일 내에 작성하지 않음
- 메타 파일은 `_` 접두사 (예: `_작성규칙.md`)

---

## 문서 구조 규칙

1. **H1 없음** — 파일명이 제목을 대신함
2. **첫 섹션은 반드시 "개념"** — 한두 문장으로 핵심 정의
3. **섹션 순서**
   ```
   개념 → 동작 원리/구조 → 예시/코드 → 비교표 → 한 눈에 요약 → 관련 문서
   ```
4. **섹션 간 구분선** `---` 사용
5. **마지막 본문은 항상 "한 눈에 요약" 코드블록**
6. **맨 끝은 "관련 문서" 섹션**

---

## 헤딩 계층 규칙

```
# (H1)    → 문서의 대주제 (큰 챕터 구분이 필요할 때)
## (H2)   → H1 아래의 세부 섹션 / 단일 주제 문서의 대주제
### (H3)  → H2 아래의 세부 개념/항목
#### (H4) → H3 아래의 더 구체적인 설명
##### (H5)→ 거의 사용 안 함 (매우 세부적인 경우만)
```

**예시 — 올바른 계층 구조**

```
# 지식그래프 핵심 개념              ← H1: 대주제 (챕터)
## 서브그래프 (Subgraph) 추출       ← H2: 세부 섹션
### 추출 방법                        ← H3: 세부 항목
### 활용                             ← H3: 세부 항목

# RAG 종류 및 비교                  ← H1: 대주제 (챕터)
## 나이브 RAG (Naive RAG)           ← H2: 하위 개념
## 그래프 RAG (Graph RAG)           ← H2: 하위 개념
## 세 가지 RAG 비교                 ← H2: 하위 개념
```

**볼드 활용 기준**

- `**용어**` — 처음 등장하는 핵심 개념
- `**결론/핵심 문장**` — 문단에서 가장 중요한 한 줄
- 남발 금지 — 강조가 많으면 아무것도 강조되지 않음

---

## 내용 작성 규칙

- 핵심 키워드는 `**볼드**` 처리
- 추상적인 설명은 반드시 코드블록이나 도식으로 보완
- 비교 대상이 있으면 반드시 **표**로 정리
- 용어는 **한글(영문) 병기** (예: 노드(Node))

---

## Obsidian 링크 규칙

- 관련 개념이 있으면 문서 하단에 **"관련 문서" 섹션** 추가
- `[[파일명]]` 형식으로 내부 링크 연결 — 확장자(.md) 제외한 풀네임 사용
- 예:
  ```
  ## 관련 문서
  - [[청킹 종류 (Chunking Types)]]
  - [[AI 모델 평가지표 (AI Model Evaluation Metrics)]]
  ```
