## 개념

쿼리의 **의미(semantic)가 비슷하면 캐시된 결과를 재사용**하는 캐싱 기법입니다.
LLM 기반 서비스에서 API 호출 비용 절감과 응답 속도 향상을 위해 주로 사용됩니다.

---

## 일반 캐싱 vs 시멘틱 캐싱

**일반 캐싱** — 문자열이 완전히 동일해야만 캐시 히트
```
"서울 날씨 알려줘"    → 캐시 저장
"서울 날씨 알려줘"    → 캐시 히트 ✅
"서울 오늘 날씨 어때?" → 캐시 미스 ❌ (다른 문자열)
```

**시멘틱 캐싱** — 의미가 비슷하면 캐시 히트
```
"서울 날씨 알려줘"     → 캐시 저장
"서울 오늘 날씨 어때?" → 캐시 히트 ✅ (의미가 같으니까)
```

---

## 동작 원리

1. 쿼리가 들어오면 **임베딩 벡터로 변환**
2. 캐시에 저장된 기존 쿼리 벡터들과 **유사도 비교**
3. 유사도가 임계값(예: 0.95) 이상이면 → **캐시 결과 반환**
4. 임계값 미만이면 → LLM 호출 후 결과를 캐시에 저장

```
[새 쿼리]
    ↓ 임베딩 변환
[쿼리 벡터]
    ↓ 유사도 검색
유사도 ≥ 임계값? ─── YES ──→ 캐시 결과 반환
    │
   NO
    ↓
LLM 호출 → 결과 반환 + 캐시 저장
```

---

## 장단점

| | 내용 |
|--|------|
| **장점** | LLM API 호출 횟수 감소 → 비용 절감, 응답 속도 향상 |
| **단점** | 임계값 설정이 까다로움 (너무 낮으면 오답 반환, 너무 높으면 캐시 무의미) |

---

## 주요 활용 도구

| 도구 | 설명 |
|------|------|
| **GPTCache** | LLM 전용 시멘틱 캐싱 라이브러리 |
| **Redis** | 벡터 검색 기능과 결합하여 사용 |
| **LangChain** | `CacheBackedEmbeddings` 등 캐싱 모듈 제공 |

## 한 눈에 요약

```
시멘틱 캐싱  →  똑같은 말을 다르게 해도 같은 답을 빠르게 돌려주는 캐시
핵심 원리    →  임베딩 유사도로 기존 쿼리와 비교
임계값       →  높을수록 엄격, 낮을수록 오답 위험
```
