# 적재와 삭제 설계안

> 나라원에서 실제로 만들어 운영해 본 것에서 뽑은, **앞으로의 범용 파이프라인** 설계안.
> 지금 구현된 것이 아니라 "이렇게 하자"는 그림이다.
> 작성 2026-09-23 · 근거는 나라원 결정기록 D15 · D37 · D48 · D50 · D56~D68

## 적재 — 파일이 들어오면

```
① 파일 도착        uploads/<날짜>/ + manifest(kind, as_of)
② 온톨로지 제시     LLM 에게 "지금 그래프가 아는 것" 을 준다 (라벨·속성·관계·어휘)
③ LLM 매핑 제안     이 파일의 칸 → 어느 라벨의 어느 속성인가
④ 자동 판정        규칙으로 걸러낸다 (타입·어휘·필수칸·중복·출처)
⑤ 사람 판정        규칙이 못 정하는 것만 사람에게 (표로)
⑥ 확정 → 릴리즈    결정을 파일로 남기고 릴리즈 문서를 만든다
⑦ 적재             한 트랜잭션 · 되읽어 대조
```

### ③ LLM 이 하는 일과 안 하는 일

| | |
|---|---|
| **한다** | "이 칸은 `Employee.name` 같다", "이건 아는 라벨에 안 맞는다" |
| **안 한다** | 그래프에 직접 쓰기, 지우기, 확정 |

**LLM 출력은 전부 제안이다.** 조회 쪽에서 LLM 이 만든 Cypher 를 `validate_cypher` 로 검사하고 읽기 전용만 허용하는 것과 같은 자리.

### ④ 자동 판정이 거르는 것

```
타입 · 어휘 · 필수 칸 · 중복 키 · 관계 양끝 라벨 · 출처 유무
```

**LLM 이 뭐라 하든 선언에 안 맞으면 거부.** (나라원: `ontology/validation.py`)

### ⑤ 사람 판정 — 규칙이 못 정하는 것만

```
같은 회사인데 이름이 다르게 적혔다      → 동일성 판정
기존 라벨에 안 맞는 칸이 나왔다         → 새 라벨? 속성? 버림?
```

**결정을 파일로 남기는 게 핵심이다.** 다음에 같은 게 와도 다시 안 묻고, 릴리즈를 다시 만들어도 같은 결과가 나온다. (나라원: `resolutions/*.csv`)

### 동일성 판별 — 같은 대상인가

파일이 계속 들어와도 노드가 하나이려면 **"이 이름이 이미 있는 그 대상인가"** 를 가려야 한다. 노드 중복을 막는 건 파일 해시가 아니라 **키**다. 파일 해시는 "이 파일을 처리할지"만 정한다.

```
0. 정규화      식별값 형식 통일(123-45-67890 → 1234567890) + 이름 정규화(㈜→(주), 공백 등)
1. 식별값 비교  같으면 확정
2. 이름 비교    정규화된 이름이 같으면 확정
3. 별칭 표      사람이 확정해 둔 별칭에 있으면 확정
4. LLM 판독    제안 → 사람 승인 → 별칭 표에 추가
```

| 단계 | 뜻 |
|---|---|
| 0 정규화 | 비교 전 전처리. 판별 단계가 아니다 |
| 1 식별값 | 사번 · 사업자번호 · 계약번호처럼 원천 시스템이 한 대상에 하나씩 붙인 값. 있으면 키로 쓰고 2~4 를 건너뛴다(속성 갱신은 그대로). 업로드 때 사람이 고른 "어느 회사 자료인가" 같은 **맥락**도 여기 — 이름이 아니라 고정 식별자다 |
| 2 이름 | 표기만 다른 것(`㈜아사달` / `(주)아사달`)을 잡는다 |
| 3 별칭 | 규칙으로 못 잡는 것 — 약칭(`과기정통부`) · 기관명 변경 · `아사달` / `(주)아사달` |
| 4 LLM | "기존 ○○ 와 같은 것 같다 + 근거" 또는 "새 대상". 승인되면 별칭 표에 남아 **다음부터 3에서 자동으로 풀린다** — 파일이 쌓일수록 사람이 볼 것이 준다 |

**식별값이 이름보다 먼저다.** 이름이 같아도 사업자번호가 다르면 다른 대상이다. 양쪽에 식별값이 있으면 식별값만 보고, 한쪽이라도 없을 때만 2~4 로 간다.

**애매하면 합치지 않는다.** 실수 비용이 한쪽으로 기운다.

```
중복 (같은 대상이 둘)     나중에 합치면 된다 — 되돌릴 수 있음
잘못 합침 (다른 대상이 하나) 관계가 섞여 어느 것이 누구 것인지 풀기 어렵다
```

LLM 이 확신해도 자동으로 합치지 않는다.

**키를 원문 이름으로 만들지 않는다.** 이름은 표시용 속성이고, 키는 식별값이나 확정된 정본으로 만든다. 나중에 이름을 확정해도 키가 안 바뀌게.

**파일을 누적으로 쓰면 합치기 규칙이 필요하다.** 종류마다 최신 하나로 교체하는 방식이면 0~1 로 충분하다. 여러 파일을 합쳐 쓰면 같은 대상이 두 파일에서 나온다 — 같은 키는 한 노드로, 속성은 기준일이 늦은 쪽이 이기고, 출처는 둘 다 남긴다.

> 나라원: 직원은 `hash(아이디, 성명)` 로 1번, 발주처는 정규화 + `resolutions/clients.csv`("Claude 제안 · 근거" + `approved_by`) 로 2~4번이 이미 돈다. 회사는 `company_key("asadal")` 고정 식별자.

#### 별칭 표 — 어디에, 어떤 모양으로

**온톨로지가 아니라 사람 결정 표(`resolutions/`)에 둔다.**

| | 온톨로지 | 별칭 표 |
|---|---|---|
| 담는 것 | **틀** — 라벨 · 속성 · 어휘 · 관계 | **개별 대상에 대한 판단** — "과기정통부 = 과학기술정보통신부 노드" |
| 바뀌는 빈도 | 드묾. 버전을 올려 바꾼다 | 파일이 들어올 때마다 한 줄씩 는다 |
| 바꾸면 | 조회가 버전 정확 일치를 요구해 **조회와 같이 릴리즈** | 다음 적재에 반영되면 끝 |

별칭이 온톨로지에 있으면 별칭 하나 승인할 때마다 버전을 올리고 조회와 맞춰 배포해야 한다.

```
온톨로지    "노드에 aliases 칸이 있다"  ← 칸 선언. 한 번만 (패치)
별칭 표     그 칸에 들어갈 값           ← 계속 는다
```

> 선언의 `synonyms`(`조직도` · `부서` …)는 **라벨 단위** 단어다 — "이 질문은 조직 라벨 얘기다"를 알아보는 용도. 대상 단위 별칭과 다르다.

**모양** — 기계 칸과 사람 칸을 나누고, `approved_by` 가 비면 적재가 안 읽는다.

```
label, alias, target_key, target_name, decision, approved_by, note, proposed_by
```

| 칸 | 누가 | 뜻 |
|---|---|---|
| `label` | 기계 | 어느 라벨 안에서의 별칭인가 |
| `alias` | 기계 | 들어온 표기 그대로 |
| `target_key` | 사람 / LLM | **가리키는 노드의 키** — 이름이 아니다 |
| `target_name` | 기계 | 사람이 읽으라고 키에서 풀어 준 이름. 다시 만들 때 새로 채움 |
| `decision` | 사람 | `same` / `different` |
| `approved_by` | 사람 | 비면 안 읽음 |
| `note` | 사람 / LLM | 근거 |
| `proposed_by` | 기계 | `llm` / `human` |

- **키를 가리킨다.** 정본 이름이 바뀌어도 별칭이 안 끊긴다
- **"다르다"도 저장한다.** 안 그러면 LLM 이 같은 쌍을 계속 다시 제안한다
- **라벨 안에서만 유효하다.** 필요하면 회사 범위도 — 같은 표기가 회사마다 다른 대상일 수 있다(두 회사의 `웹사업부`)

**멈추는 경우**

```
가리키는 키가 그래프에 없다                  → 결정을 말없이 버리지 않는다
같은 별칭이 서로 다른 두 대상을 가리킨다
같은 쌍에 same 과 different 가 같이 있다
```

릴리즈 매니페스트에 표의 해시를 남긴다 — 어떤 별칭 표로 만든 그래프인지 재현된다.

**그래프의 `aliases` 칸은 결과물이다.** 적재 때 표에서 채운다. 원본은 늘 표이고 그래프는 표에서 다시 만들어진다. 조회는 이 칸으로 약칭 질문을 찾는다. 별칭 전용 노드를 DB 에 따로 두지 않는다 — 선언 밖 라벨이라 적재가 멈추고 재현성을 잃는다.

**UI 승인이 붙으면** 형식은 그대로, 위치만 데이터 폴더로(`<데이터 폴더>/resolutions/aliases.jsonl`, 한 줄씩 추가만). 승인 철회도 줄을 지우지 않고 철회 줄을 더한다.

> 나라원: `resolutions/clients.csv` 가 이미 이 모양(기계 칸 + `value` · `approved_by` · `note`)이고, 매니페스트 `resolutions` 에 표마다 해시가 남는다.
### 새 라벨 제안 — 쌓이면 올린다

```
1회차   "이 칸 모르겠다" → 제안 목록에 기록, 그래프엔 안 넣음
2회차   또 나옴 → 횟수 증가
N회차   "이게 N번 나왔습니다. 라벨로 만들까요?" → 사람이 선언에 추가 → 온톨로지 버전 올림
```

**한 번 나왔다고 라벨을 만들지 않는다.** 라벨은 늘리기 쉽고 줄이기 어렵다. 반복이 곧 근거.

### 지켜야 할 것 — 나라원에서 배운 것

- 출처 없는 노드는 못 들어온다
- LLM 은 제안, 확정은 규칙이나 사람
- 판정이 불가능하면 멈춘다 (추측하지 않는다)
- 결정은 파일로 남아 재현된다
- 같은 입력이면 같은 해시 — 재현성이 곧 검증

## 삭제

### 기본

```
관계는 노드와 함께 반드시 지워진다        (선택 아님 — 종속 관계)
노드는 릴리즈가 "허가" 한 것만 지운다
허가 목록에 없는데 사라진 노드가 있으면 → 안 쓰고 멈춤
```

### 고아를 삭제 기준으로 쓰지 않는다

| | 예 | 관계가 다 끊기면 |
|---|---|---|
| **파생 노드** | 출처(Capture), 주소, 연락처 | **지운다** — 가리키는 데가 없으면 의미가 없음 |
| **독립 실체** | 발주처, 직원, 조직, 사업 | **안 지운다** — 나중에 다시 붙을 수 있음 |

> **"나중에 다른 곳과 관계가 생길 수 있는가"** 가 그대로 판별식이다. 생길 수 있으면 실체다.

### 실체가 고아가 되면 — 삭제 신호가 아니라 **버그 신호**

```
추출이 깨짐 · 수집이 덜 됨 · 매핑이 틀림
```

보통 이것들 때문이다. **자동으로 지우면 오류를 데이터 손실로 확정**해 버린다. 알리고 사람이 본다.

### 지우지 않고 상태로

```
없어짐   removed
퇴사     left
```

**"지금 없다" 와 "한 번도 없었다" 는 다른 사실.** 진짜 삭제는 **보관 기간 규칙**이 생겼을 때만.

### 사람이 지우고 싶을 때

| | |
|---|---|
| DB 에서 직접 | ❌ 다음 적재가 멈추고, 입력에 남아 있으면 다시 생김 |
| 입력에 적기 | ✅ 결정 파일 → 릴리즈의 허가 목록 → 적재기가 집행 |

| 왜 지우고 싶은가 | 어디를 고치나 |
|---|---|
| 원문이 틀렸다 | 원문 · 추출 규칙 |
| 원문은 맞는데 그래프에 넣기 싫다 | 사람 결정 표에 "제외" |
| 보관 기간이 지났다 | 삭제 규칙 표에 기간 규칙 추가 |

### 연쇄는 자동으로 번지지 않는다

```
"X 지워"
  ↓
드라이런 — "X 를 지우면 사업 3건이 고아가 됩니다"    ← 실행 전에 보여줌
  ↓
사람이 범위를 정함 (X 만? 3건도?)
  ↓
한 번에 실행
```

**자동 cascade 는 없다.** 한 번의 결정이 어디까지 번질지 예측이 안 되기 때문.

```
발주처 X 를 지움
  → X 만 가지고 있던 사업 3건이 고아
    → 그 사업만 가리키던 분야가 고아
      → …
```

지우라고 한 건 하나인데 일곱이 사라진다.

### 예상 못 한 고아는 리포트로

사람이 지워서가 아니라 **입력이 바뀌어서** 고아가 생길 수도 있다. 예측이 안 되니 적재 리포트에 **"고아 N건"** 을 늘 찍어 두고 사람이 주기적으로 본다.

### "지우고 나중에 다시 만든다" 의 진짜 비용

키가 내용 해시면 다시 만들어도 같은 노드가 된다. 문제는 **노드에 붙어 있던 릴리즈 밖 정보**다.

```
임베딩 벡터   다시 만들어야 함 → 돈·시간
사람 결정     노드에만 있었으면 날아감
운영 기록     적재 성공 시각 같은 것
이력          "작년에 이 발주처가 있었다" 는 사실 자체
```

마지막이 제일 크다.

## 한 장 요약

```
적재    LLM 이 제안 → 규칙이 거름 → 사람이 못 정한 것만 판정 → 결정은 파일로
동일성  정규화 → 식별값 → 이름 → 별칭 → LLM 제안 + 사람 승인. 애매하면 안 합친다
라벨    한 번 나온 걸로 안 만든다. 쌓이면 제안, 사람이 승격
삭제    허가 목록에 적힌 것만. 파생은 자동, 실체는 상태로 남김
연쇄    자동 아님. 드라이런으로 범위를 먼저 보여주고 사람이 정함
원칙    출처 없으면 안 들어온다 · 판정 불가면 멈춘다 · 추측하지 않는다
```
