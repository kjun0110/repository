## 개념

- **릴리즈 (`release.json`)** — 한 번의 적재가 넣을 그래프 전체와 그 재료의 지문을 담은 문서. `manifest`(순번·이전 해시·온톨로지·스냅샷·결정 표·명단 해시·라벨별 건수) · `graph` · `report` 셋으로 이뤄진다
- **매니페스트 해시** — 매니페스트 바이트의 sha256. **같으면 재료가 전부 같다.** 오늘 코드 리팩토링마다 이 값이 그대로인지로 무회귀를 증명했다
- **섀도우** — 로컬 Docker 로 띄운 빈 Neo4j. 운영과 같은 `ingestion.load` 경로를 대상만 바꿔 돌린다
- **부분 거부** — 틀린 후보만 빼고 나머지를 넣는 검증 방식. 구조 오류 · 거부율 10% 초과 · 회사 노드 거부일 때만 전부 거부한다
- **서빙 호환 버전 목록** — 조회 API 가 받아들이는 DB 온톨로지 버전들. 적재가 만드는 버전과 분리해 배포와 적재 사이의 틈을 없앤다
- **릴리즈 밖 칸 (`managed`)** — 선언에는 있으나 릴리즈 해시와 적재 대조에서 빠지고, 적재기가 지우지 않는 칸. `embedding_text` · `embedding` · `embedding_source_sha256`
- **원천 재료 해시** — 임베딩을 다시 만들지 판단하는 기준. 노드와 이웃의 재료 + 생성 모델 + 프롬프트 버전을 묶은 해시
- **`site_status`** — 사이트에서 사라진 노드를 지우지 않고 `removed` 로 표시하는 칸. 직원의 `left` 와 같은 방식

##### S15 — 레코드를 노드·관계로
원문 한 곳 = 한 건이던 레코드를 그래프 단위로 합쳤다. 선언 0.4.0 의 수와 정확히 맞는다.

##### S16 — 확정 JSON 을 읽는 로더와 DDL

## 5. 직원 적재 — 0.4.0 에 포함하고 0.4.0 확정

##### 결정
- 운영 적재 전에 직원도 넣음. 원천은 엑셀, 휴대폰·직장번호는 챗봇이 답해도 됨
- 버전은 0.5.0 을 따로 두지 않고 **0.4.0 에 포함**(확정 전이라 `since` 만 바꿈)
- 원천 파일 `private/hr/인원현황-YYYY-MM-DD.xlsx`, 파일명 날짜 = 명단 기준일. 날짜 없음 · 머리글 다름 · 수식·병합 칸이면 멈춤
- 새 어휘 값이 오면 엑셀 기준으로 어휘를 고침. 대표자 불일치는 경고만
- 조회 API 는 다른 사람이 이후 단계에서 맡음. 여기서는 적재만

> **정정.** [[0914_KG - 나라원 · 직원 칸은 명단으로 확정했고, 규칙 추출이어야 재적재가 멱등하다]] 에서 직원 키를 `sha256(직원아이디 | 입사일)` + 입사일 정정 탐지 규칙으로 정했다. 오늘 "입사일 정정이든 재입사든 덮어쓰면 된다"는 결정에 따라 **`sha256(직원아이디 | 성명)`** 으로 바꿨다. 같은 날 문서의 "0.5.0 전용 칸"도 0.4.0 포함으로 바뀌었다.

```

대량 퇴사   직전 재직자의 10% 초과면 멈춤 — 잘못된 명단 파일 방지, 맞으면 --allow-many-left
옛 명단     직전 적재보다 이른 날짜면 멈춤

## 6. 버전 한 곳, 서빙 호환 목록 (D46 · D47)

##### 문제 — 버전이 두 곳에 있고 서로 맞는지 아무도 안 봄
`declaration.py` 의 `VERSION` 과 `registry.py` 의 `ONTOLOGY_VERSION`. 선언만 0.4.1 로 올려 굽고 확정하면 **적재와 서빙은 에러 없이 0.4.0 을 계속 읽는다.**

##### 택한 안 — `ontology/version.py` 한 줄
실행 쪽은 작성 쪽(`ontology.definition`)을 import 하지 않는다는 규칙 때문에 공통 위치는 실행 쪽이어야 한다. 굽기 결과, 확정본 sha `07b4259b…`, 드라이런 해시 `f5a6ce8a…` 가 모두 그대로였다.

##### 두 번째 문제 — 배포와 적재 사이의 틈
서빙이 "DB 버전 == 코드 버전"만 허용하면, 서빙을 먼저 배포하든 적재를 먼저 하든 그 사이에 검색이 503 이다.

| 안 | 판정 | 사유 |
|---|---|---|
| 짧은 점검 시간 | 변경·삭제 버전에만 | 몇 분 조회 중단 |
| **서빙 호환 목록** `SERVING_COMPATIBLE_VERSIONS` | 채택 | 추가만 하는 버전은 옛·새 버전을 함께 허용해 끊김 없음 |
| DB 두 벌 두고 전환 | 기각 | Neo4j CE 는 DB 하나, 인스턴스 추가 운영은 과함 |
| 서빙 시작 시 확정본 파일 존재 검사 | 기각 | 실제 위험(서빙 버전 ≠ DB 버전)과 다른 것을 확인함 |

적재 버전이 호환 목록에 없으면 import 에서 멈춘다. 항목의 `ontology_version` 에는 코드 상수가 아니라 DB 에 실제로 든 버전을 넣는다. 확인 20개가 통과했다.

## 8. 임베딩 설계 — 벡터는 두 라벨, 문장·벡터는 릴리즈 밖

##### 대상 — 판단이 세 번 바뀜

```
1차   사업 · 보유기술(조각 노드) · 사업분야 · 연혁 + 회사 · 사무소도 벡터
2차   회사 · 사무소 · 연혁 · 사업분야 → 고정 컨텍스트로 철회
       (회사는 노드가 1개라 찾는 단계가 무의미하고, 사업 벡터와 점수 경쟁하다 밀려날 수 있음. 합쳐 약 3,600자)
3차   보유기술 조각 노드 → 새 노드 없이 "큰 글(headlines)" 로 대체
```

2차에서 "노드 안에 벡터 목록 칸"을 선택지로 냈던 것은 틀렸다. **Neo4j 벡터 인덱스는 노드 하나에 벡터 하나만 본다.** 새 노드를 원치 않는다는 요구에 맞춰, 페이지의 제목·소제목·소개문·슬로건만 모아 검색 문장 재료로 삼았다. AI 채팅 본문 6,812자가 342자가 됐다. 답변 근거는 여전히 `body_text` 전체다.

##### 최종 분담

| 방법 | 대상 |
|---|---|
| 벡터 | 사업 208 · 보유기술 12 (인덱스 2) |
| 고정 컨텍스트 | 회사 · 사무소 · 연혁 · 사업분야 |
| 이름 검색 + 그래프 | 조직 · 발주처 (이름이 짧고 비슷해 벡터가 못 가림) |
| 템플릿 조회 | 직원 (개인정보, 정확 조건) |
| text2cypher 보조 | 개수 · 조건 · 목록 |

##### 모델
BGE-M3(사내 실행)를 먼저 고려했다. 확인해 보니 **Chatty 는 `text-embedding-ada-002`(1536) 를 쓰고 BGE 임베딩 API 는 없었다.** 결국 ada-002 로 통일하고, 문장 생성은 `gpt-5.6-luna` 로 정했다. 질문 임베딩도 같은 모델이어야 한다.

##### 저장 — 검토한 안과 기각 사유

| 안 | 판정 | 사유 |
|---|---|---|
| 벡터를 릴리즈에 포함 | 기각 | 1536 × 220 실수가 문서에 들어가고, 실수 표기 차이로 해시가 흔들림 |
| 적재 뒤 벡터를 따로 씀 (보존 규칙 없음) | 기각 | 적재기가 속성을 통째로 교체해 지워지고, 그 전에 "DB 가 직전 릴리즈와 다름"으로 다음 적재가 멈춤 |
| **벡터는 릴리즈 밖 칸** | 채택 | 대조에서 빼고 쓸 때 지우지 않음 |
| 생성 문장을 파일로 고정해 커밋 | 기각 | 관리할 파일이 생김. 문장도 릴리즈 밖에 두면 해시는 이미 고정됨 |
| **생성 문장도 DB 에서 관리** | 채택 | 적재는 OpenAI 없이 결정적, GPT 호출은 임베딩 단계 한 곳 |

##### 증분
`embedding_source_sha256` = 원천 재료 + 모델 이름 + 프롬프트 버전이다. 사업의 재료에는 **이웃(발주처 이름·유형, 사업분야 이름)** 이 들어간다. 결정 표에서 발주처 이름을 확정하면 그 발주처의 사업 문장만 다시 만들어진다. 모델이나 프롬프트를 바꾸면 전부 다시 만든다.

##### 사이트에서 사라진 노드
실제 삭제는 기각했다. 사이트 일시 오류로 빠진 것도 지워지고, 이전 답변의 근거가 사라진다. 사이트 라벨 8종에 `site_status`(`present` / `removed`) 를 두고, 라벨별 직전의 10% 를 넘게 사라지면 멈춘다.

## 9. 0.4.1 구현과 실제 OpenAI 시험 — 이름을 바꿔 쓰는 2건

##### 구현 중 위험 — 확정본 0.4.0 이 안 읽힐 뻔함
로더는 파일을 새 모델로 다시 구운 바이트와 비교한다. 모델에 칸을 추가하면 옛 파일은 바이트가 달라 거부된다. 바이트 규약을 "파일에 적힌 칸만 다시 쓴다"로 바꿔 0.4.0 · 0.4.1 이 모두 읽힌다.

##### 그 김에 — AI 번역 페이지의 `</p>` 누락
큰 글을 뽑다가 AI 번역 페이지에 닫히지 않은 문단이 있어 뒤의 제목 두 개를 놓치는 것을 발견했다. HTML 규칙대로 그 문단을 닫게 고쳤다. 게시판 `</tr>`(0911)에 이어 두 번째로 닫히지 않은 태그다.

##### 실제 호출 1차 (프롬프트 v1)

```
220건 1분 5초 · 재실행 호출 0
사업명 208/208 · 계약일 208/208 · 보유기술 이름 12/12
발주처명 206/208   "대한무역투자진흥공사" → "대한무역투자진흥사" (2건)
AI 검색            이름뿐인데 "인공지능 기반 검색 기술을 활용합니다" 를 지어냄
말투               ~했다 / ~입니다 혼용, "검색할 수 있습니다" 같은 군더더기
```

##### 택한 안
- **이름 검사:** 생성 뒤 사업명·발주처·계약일(보유기술은 이름)이 그대로 들어갔는지 확인한다. 빠지면 빠진 항목을 짚어 한 번 다시 부르고, 그래도 빠지면 규칙으로 만든 사실 나열 문장을 쓴다
- **프롬프트 v2:** 합니다체, 이름·날짜 변형 금지, 메타 문구 금지, 입력에 없는 회사명 금지
- **규칙 문장 조사:** 마지막 글자 받침으로 은/는 선택. 한글이 아니면 `은(는)` 유지
- **AI 검색:** 원문을 열어 보니 본문 영역이 0개이고 페이지 전체가 동작하는 검색 앱이었다. "이름만 두기"를 추천했으나 기각됐다. 대신 검색 화면에 실제로 적힌 기능 이름(자연어 검색 안내, 검색분류 15종, 검색범위, 답변요약 등)을 이 페이지 전용 규칙으로 뽑아 `headlines` 로 쓴다. `{{ }}` 자리표시는 뺀다

##### 결과 — 확정본으로 최종 확인

| 항목 | 결과 |
|---|---|
| 확정본 | `versions/nara1-0.4.1.json` · sha `38d15d58…` |
| 적재 | 순번 1 · 매니페스트 `fd11c4b5…` · 거부 0 · 검토 0 |
| 임베딩 | 220건 = 바로 생성 215 · 재생성 4 · 규칙 문장 1 |
| 재실행 | 호출 0 |
| 이름 보존 | 사업명 · 발주처 · 계약일 각 208/208 · 보유기술 12/12 |
| 말투 | 합니다체 아닌 문장 0/462 · 군더더기 0 |

##### 한 명령 적재
`load --write` 가 확인 통과 뒤 임베딩까지 이어 돈다. 임베딩은 적재의 일부라, 옵션을 따로 붙이게 하면 빼먹는다. 예외는 `--skip-embed` 로 둔다. OpenAI 키가 없으면 DB 접속 전에 멈춘다. 임베딩만 실패하면 적재 결과는 남기고 종료코드 1이고, 다시 치면 남은 것만 채운다.

도커 멈춤→적재→재빌드 셸 스크립트는 기각했다. 첫 운영 적재는 사람이 단계 사이를 봐야 하고, 자동화 때 어차피 새로 짠다.

키 없음 → 접속 전 멈춤, 스키마도 안 생김 · 임베딩만 실패 → 종료 1, 재실행 시 남은 1개만
```

## 11. 곁가지 조사 — 수원 부서 API · KGreference

##### 수원 부서 API — 복호화 방식 확정
`.env` 를 읽게 하고, 실행마다 `output/<실행시각>/` 에 응답 원본 → 메타 → 암호문 → 복호화 → 정리본 6개 파일로 남기게 했다.

```
HTTP 200 · 약 1.1초 · 응답 약 1.5MB
복호화   AES-256-CBC · 키 = 암호화 키 32자 · IV = 키 앞 16자 — 여러 조합 시도 중 성공한 방식
결과     5,103행 — 부서 수가 아니라 업무 행 수 (한 부서에 업무가 여럿이면 반복)
빈 값    telNum 423 · roleNm 4 · deptNm · deptPathNm 0
```

시도 루프를 확정 방식 하나로 줄이는 정리는 제안만 하고 하지 않았다.

##### KGreference 폴더 — 오픈소스 `ai-knowledge-graph` (Apache 2.0)
문서 → 청킹(코드) → 청크마다 LLM 트리플 추출 → 엔티티 정규화 → LLM 관계 추론 → JSON 파일 하나 → HTML 뷰어 순서다.

| 확인 | 결과 |
|---|---|
| RDF 인가 | 아님. URI · 어휘 · SPARQL 없음. 관계에 속성을 붙이는 속성 그래프 모양 |
| DB | 없음. `knowledge_graph.json` 을 매번 메모리에 올려 BFS. Neo4j 는 Cypher 내보내기만 |
| 온톨로지 | 없음. 타입 9개 고정, 관계 이름은 LLM 이 자유롭게 |
| 임베딩 | 없음 |
| 한국어 질의 | 매칭 정규식이 영문·숫자만 남겨 **내용어 0건** (실측) |
| 파싱 | 원문 구조 해석은 LLM 에 맡김. HTML 파서 없음, DOCX 는 표 누락 |

판정은 **나라원 파이프라인으로는 안 맞고 부품만 참고**다. 나라원 원칙("규칙이 뼈대, LLM 은 제안만", 추측 금지, 결정적 추출)과 방향이 반대다. 가져갈 만한 것은 `llm.py` 의 잘린 응답 감지 · JSON 복구 · `sha256(모델, 프롬프트, 파라미터)` 캐시와 vis-network 뷰어 템플릿 정도다. 잘린 배열 살리기(`_salvage_objects`)는 제안 흐름에서는 꺼야 한다.

## 재사용 가능한 판단

- **코드를 옮기거나 지웠으면 매니페스트 해시로 증명한다.** 오늘 S19c, 버전 정리, 리팩토링 네 묶음 모두 해시가 그대로였다
- **롤백은 가짜 DB 로는 절반만 확인된다.** 실제 Neo4j 에서 "중간에 쓴 ReleaseHead 까지 되돌려짐"을 봐야 트랜잭션 경계가 증명된다
- **틀린 것만 빼되 큰 이상은 멈춘다.** 부분 거부와 전부 거부는 둘 중 하나가 아니라 기준선(거부율 · 핵심 노드)으로 나뉜다
- **규칙이 틀렸으면 규칙을 고친다.** 거부된 후보를 사람 승인으로 통과시키는 길을 만들지 않는다
- **"없어지면 멈춤"은 두 번째 적재에서 늘 걸린다.** 관계 삭제와 노드 상태 표시를 먼저 설계해야 증분이 돈다
- **정본이 두 곳이면 서로 맞는지 검사가 없는 한 조용히 어긋난다.** 버전 문자열도 마찬가지다
- **서빙 버전 정확 일치는 배포와 적재 사이에 틈을 만든다.** 추가만 하는 버전은 호환 목록으로 넘긴다
- **적재에 비결정적인 값을 넣지 않는다.** LLM 문장과 실수 벡터는 릴리즈 밖에 두고 원천 재료 해시로 증분한다
- **LLM 생성 문장에는 필수 항목 검사와 규칙 문장 대체를 붙인다.** 206/208 은 검색 품질보다 신뢰 문제다
- **사실이 없는 입력을 LLM 에 주면 지어낸다.** 먼저 원문을 열어 쓸 수 있는 사실이 정말 없는지 본다(AI 검색은 화면에 기능 이름이 있었다)
- **추천을 두 번 이상 바꾸면 틀렸던 전제를 적는다.** 오늘은 "노드 안 벡터 목록"이 성립하지 않는 전제였다
- **원문에 없는 값은 원천 밖에서 확인한다.** 서버가 잘라 보낸 이름은 재수집으로 복원되지 않는다
- **남의 문서는 요청 없이 고치지 않는다.** 추가할 내용은 같은 폴더의 새 파일로 둔다
- **오픈소스를 볼 때는 우리 원칙과 방향부터 대조한다.** 기능 목록이 비슷해도 "LLM 이 뼈대"면 부품만 가져온다

## 한계

- **운영 적재는 하지 않았다.** 브랜치도 원격에 없다(17:37 기준). 운영 DB 가 외부 주소로 보이는 인스턴스와 내부 주소 인스턴스가 같은지는 확인하지 않았다
- **OpenAI 키가 `.env` 에 들어가 커밋 `758e274` 에 포함됐다.** 원격 저장소에 올리면 기록에 영구히 남는다
- **직원 명단(엑셀, 212명 개인정보)이 커밋 `3d626e2` 에 들어갔다.** 원격 주소가 https 가 아니다
- **확인 스크립트(게이트)는 `.local/` 에만 있다.** 저장소에 남는 자동 시험이 없다
- **실제 롤백은 섀도우 1회 · 2가지 경우만 봤다**
- **생성 문장은 섀도우와 운영에서 다를 수 있다.** 같은 재료라도 LLM 호출이 다시 일어나기 때문이며, 해시 비교 대상이 아니다
- **규칙 문장으로 들어간 1건(2022년 바이코리아)은 luna 가 두 번 모두 발주처 이름을 바꿔 썼다.** 원인은 모른다
- **AI 검색 `headlines` 는 한 페이지 전용 규칙이다.** 화면이 개편되면 멈춤 검사로 드러난다
- **수집 세대가 없다.** 사이트를 다시 수집해 폴더를 추가하면 같은 주소 다른 내용으로 적재가 멈춘다. 노드 실제 삭제도 없다
- **API 계약 "1"을 유지한 채 응답 칸 3개가 빠졌다.** Chatty 가 그 칸을 읽는지는 확인하지 않았다
- **기관유형 동률 3곳은 사이트 분류가 아니라 법적 지위로 정했다.** 사이트와 다른 값이 들어간다
- **잘린 발주처 18곳 이름은 사업명 근거 제안을 승인한 것이다.** 계약 자료로 대조한 것은 1곳뿐이다
