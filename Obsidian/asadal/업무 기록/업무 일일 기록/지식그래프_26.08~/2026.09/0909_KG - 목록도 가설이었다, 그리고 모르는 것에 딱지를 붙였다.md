## 개념

- **격리(quarantine)** — 모르는 것을 지우지도 멈추지도 않고 `:Pending` 딱지를 붙이는 것. 격리→분류→승격 루프의 첫 단계
- **분류 / 승격** — 이유마다 "누가 푸나"(규칙/사람)를 선언하고, 사람 답이 오면 다음 실행에 딱지가 저절로 떨어지는 것. 승격 코드는 따로 없다 — 매 실행 재판정이 곧 승격이다
- **멱등(idempotent)** — 원천이 같으면 몇 번을 돌려도 그래프가 같은 것. 자동으로 돌리려면 이게 먼저다
- **파싱 실패 vs 동일시 실패** — 값이 페이지 안에 있는데 못 집은 것 / 값은 뽑았는데 우리 그래프(또는 세상)의 무엇인지 모르는 것. 전자는 기계가, 후자는 사람이 확정한다
- **메타스키마** — 선언이 쓸 수 있는 키의 목록(`meta.yaml`). 상호참조 검사는 "가리키는 것이 있나", 메타스키마는 "그 키가 실재하나"를 본다
- **읽는 사람 없는 숫자** — 기준선에 적었는데 아무도 비교하지 않는 값. 적재만 하고 안 읽는 관계와 같은 병
- **아직 안 걸린 숫자** — 어느 값을 넣어도 지금 데이터에서 결과가 같은 임계. 틀린 값이 아니라 첫 사례가 안 온 값
- **게시판 관리부서(MANAGED_BY)** — 그 게시판을 운영하는 부서. 글쓴이(POSTED_BY)와 다르다 — 보도자료는 공보관이 관리하고 글은 각 부서가 쓴다

## 4. 45번 — 소비자 하나가 찾은 구멍

##### 방법

gold 48문항 중 서식 문항 7개, 축 없는 3개에 축을 붙이려 했다. **셋 다 못 붙였다** — 전기차 서식은 그래프에 없고(서식자료실에도 없음), 체육시설 대관은 사이트에 없고, 공동주택은 질문에 서식 낱말이 없어 첨부 갈래가 안 열린다(설계대로).

서식 낱말을 넣어 새로 재봤다.

```
"공동주택 보조금 지원사업 신청서"
  1위   한옥건축등보조금지원사업              ← 오답
  첨부  한옥 건축수선 보조신청서 2건          ← 오답

```

##### 원인 — 44 가 아니라 POSTED_BY

그 글들이 실린 게시판 `1327 공동주택관리 보조금 지원사업` 은 **74건 전부 부서 칸이 없다.** link_depts 3단계(이름·전화·구)가 전부 시도조차 못 하고, 조직 경로(공동주택과 → 팀 → 글 → 파일)가 끊긴다.

```
칸 없는 게시판   주택 정보마당 639/639 · 지구단위계획 319/319 · 일자리 소식 238/238 · 1327 74/74
칸은 있는데 못 붙임   민원서식자료실 196/469 · 보도자료 182/2,230   ← 12번
```

##### 판정 — 방아쇠 대기

처방은 선언 한 줄씩(`sites/suwon.yaml boards[].dept`)이지만 **판단 4개짜리다.** '주택 정보마당' 639건이 한 부서 것인지 모른다. 틀리게 붙이면 엉뚱한 부서 서식이 나간다 — "모르는 채로 거는 것보다 안 거는 편이 낫다". 실측 피해는 내가 만든 질문 하나고 기존 48문항은 통과한다. 24번이 실제 질문으로 이 게시판을 치거나 12번을 손댈 때 같이 한다.

**44 는 크기(507)에서 나왔고, 45 는 소비자(질문 하나)에서 나왔다.** 507건을 다 이어도 이 질문은 못 맞힌다.

##### 곁가지 — 속성 이름 하나로 숫자가 틀렸다

처음 `a.dept IS NULL` 로 세서 2,125건 전부가 '칸 없음'으로 나왔다. 속성은 `dept_name` 이다. 바로 세니 1,596 · 278 · 263. **한 부류가 100% 로 나오면 질의부터 의심한다** — "0 이 나오면 도구 의심"의 쌍둥이.

## 5. 격리 루프 1단계 — 모르는 것에 딱지를 붙였다

##### 문제

모르는 것을 만났을 때 파이프라인이 하는 일이 둘뿐이었다. **멈추거나**(어휘 밖 값 → FAIL), **조용히 넣거나**(부서 못 찾은 글을 연결 없이 적재). 둘 다 "사람 개입 최소화"와 반대다. 멈추면 사람이 와야 하고, 조용히 넣으면 얼마나 모르는 채로 들어갔는지 아무도 모른다 — 45번의 1,596건이 리포트 어디에도 없었던 것이 그 증거다. 리포트는 "못 붙인 것"만 세고 "시도조차 못 한 것"은 안 셌다.

##### 만든 것

```
선언   schema.yaml quarantine: { label: Pending, reasons: 5종 } — 이유마다 label·ko·desc
       meta.yaml 에 절 추가. _check_keys 가 점 경로(quarantine.reasons)를 읽게 확장
       schema._validate: 이유의 label 이 실재해야 · 표지 라벨은 labels 에 있으면 안 됨(시험 2개, 19개)
적재   nodes/16 quarantine()  POSTED_BY 없는 글 → dept_column_empty / dept_ambiguous / dept_missing
                              unknown 유형 → article_type_unknown
       nodes/01 load_level()  어휘 밖 unit_level → 값을 비우고 :Pending(unit_level_unknown)
       둘 다 매 실행 재판정 — 연결이 풀리면 딱지가 떨어진다. 가장 싼 승격
검사   validate/06  격리 노드는 required·slots 검사에서 뺀다(불완전해도 되는 것이 격리)
                    이유가 선언 밖이면 FAIL · 이유의 라벨이 어긋나면 FAIL · 이유별 [참고]
       validate/03  이유별 수를 기준선에
       게이트       새 이유의 출현만 WARN. 크기는 알림만 — 소식 게시판은 매일 는다
검색   손대지 않음. 부서 모르는 글도 글 자체는 맞는 글이라, 감출지는 이유별로 정할 일
```

## 6. 격리 루프 2단계 — 기계가 묻고, 사람이 답하고, 기계가 반영한다

##### "추론 기반 검색"은 물어볼 것이 아니었다

OWL 추론은 RDF 트리플 위의 얘기고 Neo4j 엔 그 추론기가 없다. 속성 그래프에서 되는 추론 셋 — **질의 시점 다중 홉**(`PART_OF*0..5`) · **규칙 물질화**(`inference: chain` → `IN_CHARGE_BUREAU` 583, OWL 의 property chain 에 해당) · **선언 검증**(range·cardinality·disjoint·acyclic 을 적재기가 막음) — 이 전부 이미 있다. 발주처에 물을 일이 아니라 우리 스택에서 그 말이 뜻할 수 있는 것을 정직하게 적으면 끝이다. 23-b·27 닫힘.

##### 분류 — "누가 푸나"를 선언에 적었다

```yaml
dept_column_empty:    { resolve: human, ask: board,     hide: false }   # 게시판이 부서를 안다
dept_ambiguous:       { resolve: rule,                  hide: false }   # 서브도메인이 푼다. 묻지 않는다
dept_missing:         { resolve: human, ask: dept_name, hide: false }
article_type_unknown: { resolve: human, ask: board,     hide: true  }
unit_level_unknown:   { resolve: human, ask: name,      hide: true  }
```

**묻는 단위가 요점이다.** 부서 칸 없는 1,596건을 글마다 물으면 질문 1,596개다. `ask: board` 면 13개다. 로드 시점에 human 이면 ask 필수, rule 이면 ask 금지, hide 는 bool 을 검산한다(시험 +2 = 21).

##### 질문 — `review/01_ask.py` → `decisions/pending.yaml`

결정 파일 형식(value·why·decided·by)을 그대로 쓴다. 묻는 항목은 네 칸이 null 이고 사람이 채우면 결정이 된다. **답한 항목은 절대 덮어쓰지 않고**, 물을 것이 없어진 질문은 지운다. 힌트는 글 본문의 실무조직 이름과 직원 전화 대조 상위 셋 — 근거가 없으면 비워 둔다.

```
열린 질문 59개 — 게시판 13 · 부서명 46 · 조직 0
  1171 주택 정보마당 639      [공동주택과 (본문) 44건 · 재난대응과 6 · 관리팀 5]
  1303 지구단위계획 319       [지구단위계획과 (본문) 5건 · 토지정보과 4 · 지구단위계획1팀 (전화) 1]
  1153 일자리 소식 238        [운영팀 11 · 공무직운영팀 (전화) 10 · 행정지원과 10]   ← 여러 부서
  1327 공동주택관리 보조금 74  [공동주택과 (본문) 9건 · 관리팀 2 · 임대사업관리팀 2]
```

##### 승격 — 코드가 아니라 "매 실행 재판정"이다

`nodes/16` 의 link_depts 4단계(`apply_pending_decisions`)가 board/dept_name 답을 읽어 `POSTED_BY` 를 걸고, `nodes/01` 이 name 답을 `unit_level` 로 쓴다. `'-'` 는 "연결하지 않는다" — 그 글들은 격리도 안 한다(모르는 것이 아니라 정한 것이다). 연결되면 다음 `quarantine()` 재판정에서 딱지가 **저절로** 떨어진다. 승격 코드는 따로 없다.

`hide: true` 는 `status = 'quarantined'` 로 숨긴다 — 검색·임베딩이 전부 `status = 'active'` 를 거르므로 **새 필터를 만들지 않았다.** `validate/06` 이 hide 선언과 status 의 불일치를 FAIL 로 잡는다(음성: 격리 글 하나를 quarantined 로 바꾸니 `[위반]`).

##### 한 바퀴 돌려 봤다

임시로 `1327 → 공동주택관리팀`, `미세먼지대응팀 → '-'` 를 적고 돌렸다.

```

"공동주택 보조금 지원사업 신청서"  첨부 축 '공동주택보조금지원신청서식' 적중  False → True

```

45번이 루프 안에서 풀리는 것을 확인했다 — **기계가 묻고 → 사람이 답하고 → 기계가 반영하고 → 숫자가 줄고 → 게이트가 확인한다.**

## 8. "저것들은 왜 몰라? URL 줘봐" — 사이트가 이미 말하고 있었다

##### 물음이 진단을 뒤집었다 (오늘 13번째)

`pending.yaml` 의 게시판 13개 질문을 내밀자 사용자가 **"왜 모르냐, 어느 페이지냐, URL 을 달라"** 고 물었다. URL 을 뽑으려 실제 페이지를 열었더니 **부서 칸이 없는 게 아니라 우리가 안 보는 자리에 있었다.**


##### 그런데 글쓴이 부서가 아니다 — 관계를 나눴다


즉 하단은 **그 게시판을 운영하는 부서**다. `POSTED_BY` 로 넣으면 "이 보도자료는 공보관이 썼다"는 거짓말이 된다.

```yaml
  from: Board
  to: OrgUnit

```

## 10. "규칙 실패하면 LLM" 을 실제로 해 보고 접었다

##### 제안

수집에서 규칙이 못 뽑은 것만 LLM 에 한 번 더 물어 정돈하면 어떤가. **좋은 제안이다** — 수집 단계라 결과가 JSON 에 박히고, 적재는 그 파일만 읽으므로 멱등이 안 깨진다. 비용도 예외 건만이라 전량 LLM 의 몇 분의 일이다.

##### 만들고 돌렸다

발급처가 대상이었다. `ontology/documents.py` 의 접미사 규칙 10개가 서류 609종 중 387종(74%)을 덮고 222종이 `None` 이다.

```
scraping/16_resolve_issuers.py   규칙이 실패한 222종만 LLM 에. enum 은 규칙과 같은 목록(12종)
documents.py issued_at()          규칙 먼저 → 실패하면 파일에서 읽음. 파일 없으면 폴백 없이 돈다
결과                              222종 중 54종 채움 · 168종은 LLM 도 "모른다"
```

##### 54종을 눈으로 다 읽었다 — 9종이 틀렸다 (17%)

```
수출말소 취소확인서 1부(수출업체에서 발급)  → 은행       이름 안에 답이 써 있는데 틀렸다
RFID카드 분실신고                      → 은행       음식물쓰레기 카드다. 동 행정복지센터
공장등록증명서                          → 세무서      시·군·구 또는 산업단지공단
특수교육대상자 진단･평가 결과 통지서         → 의료기관    교육청
조기폐차보조금지급대상 확인서               → 동 행정복지센터 한국자동차환경협회
1·2차 의무교육확인서                    → 접수처 비치   학교 (목록에 '학교'가 있는데도)
건축물 관리대장 1부                     → 대법원 …     정부24
설립신고: 관할 행정기관은 …                → 대법원 …     애초에 서류가 아니라 문장 조각
```

맞은 39종(72%)은 쓸 만하다 — 주민등록 등초본 → 동 행정복지센터, 산모수첩 → 의료기관, 목줄·케이지·사진 → 본인 소지.

##### 왜 틀렸나 — 내가 문제를 잘못 분류했다

실패를 둘로 갈라 놓고도 발급처를 **파싱 실패**에 넣었다. 다시 보면 **동일시**다.

```
파싱   값이 페이지 안에 있는데 규칙이 못 집었다      → LLM 이 다시 읽으면 된다
동일시  서류 이름만 있고 발급 기관은 어디에도 없다    → 세상 지식으로 골라야 한다
```

"각서를 어디서 떼나"는 문서 어디에도 안 적혀 있다. **읽는 문제가 아니라 아는 문제**다.

그리고 틀린 9종 중 4종은 **정답이 목록에 없어서 강제로 틀렸다**(교육청·산업단지공단·자동차환경협회·수출업체). enum 으로 가두면 "모른다"보다 **가장 비슷한 오답**을 고르는 압력이 생긴다. 객관식에 정답이 없을 때와 같다.

##### 그런데 이미 LLM 값이 그래프에 2,400건 들어가 있다

"LLM 이라 안 넣는다"는 원칙이 아니다. 지금도 이만큼이 LLM 판정이다.

```
DocumentType 609 · REQUIRES 890 · AVAILABLE_VIA 376 · FOR_TARGET 271 · content_type 644
```

그래서 기준을 다시 세웠다. 발급처는 **넷 중 셋이 안 맞았다.**

```
① 답이 원문에 있나       채널·대상층·구비서류 ✔ 본문에 있다 / 발급처 ✘ 없다   ← 가장 크다
② 선택지 안에 정답이 있나  채널 10종 ✔ / 발급처 12종 ✘ 교육청·공단이 빠졌다
③ 틀리면 티가 나나       채널 ✔ 답변에 바로 / 발급처 ✘ 시민이 헛걸음해야 안다
④ 검증 축이 있나         구비서류 ✔ 첨부 축 4문항 / 발급처 ✘ 0개
```

`content_type` 이 발급처처럼 "판단"인데도 LLM 을 쓰는 이유가 ③이다 — 틀리면 `validate/01` 검사가 바로 깨진다. 규칙으로는 73~82%밖에 못 맞힌다는 실측도 코드에 남아 있다.

##### 접었다 — 빈칸이 오답보다 낫다

이미 코드의 원칙이었다. `documents.py` *"못 맞히면 None 이고, 그건 '모른다'가 정확한 답이라 지어내지 않는다"* · `nodes/16` *"모르는 채로 거는 것보다 안 거는 편이 낫다"*.

```
빈칸   시민이 한 번 더 물어야 한다. 불편하지만 손해는 없다. 그리고 **세어진다**
오답   시민이 은행에 갔다 헛걸음한다. 우리를 못 믿게 된다. 그리고 **아무 데도 안 뜬다**
```

뒤엣것이 더 크다. 오늘 하루 잡은 것이 전부 그 부류였다 — 유령 직원 22명 · 죽은 링크 3건 · 부서 없는 게시글 1,596건. 전부 조용히 들어가 있었다.

배선은 남기고 파일만 비웠다(파일이 없으면 폴백이 자동으로 꺼진다). 나중에 사람이 검토해 채우고 싶을 때 `scraping/16` 으로 제안을 받아 손으로 고치면 된다.

##### 남은 판단 — 사람이 54개를 한 번 훑을 것인가

권한다. 39개는 제안이 맞으니 그대로, 9개만 고치고, 애매한 6개는 비우면 된다. 30분이고 `decisions` 에 박히면 다시 안 묻는다. 그것이 오늘 만든 격리→질문→승격 루프가 원래 하려던 일이다. 다만 급하지 않다 — 지금도 74%가 규칙으로 채워져 있고 나머지는 빈칸이라 틀린 답은 안 나간다.

## 재사용 가능한 판단

- **검토 단계의 목록은 "고칠 것"이 아니라 "재볼 것"이다.** 실행 직전 10분이 가짜 경보 510건보다 싸다
- **크기를 보고 미루기 전에 원천 페이지를 한 장 연다.** 45·46 둘 다 그랬다 — 1,596건과 유령 직원 22명이 원천에 답이 있었다. 5분 vs 반나절
- **추측(자카드·LLM)으로 짝지으려 할 때, 원천에 열쇠가 있는지 먼저 본다.** org_key 의 부서 코드가 916/937 을 결정적으로 갈랐다
- **불변식은 "그래야 한다"가 아니라 "지금 그렇고 앞으로도 그래야 한다"를 재야 한다.** 510건이 설계였다
- **"근거 없음"과 "아직 사례 없음"은 다르다.** 어느 값이든 결과가 같은 임계는 틀린 게 아니라 안 걸린 것이다
- **기준선에 적는 것과 읽는 것은 다르다.** 게이트가 안 보는 숫자는 적재만 하고 안 읽는 관계와 같다
- **한 부류가 100%(또는 0%)로 나오면 질의부터 의심한다.** 속성 이름 하나(`dept` vs `dept_name`)로 2,125건이 전부 한 부류로 보였다
- **리포트에 찍는 것과 그래프에 딱지를 붙이는 것은 다르다.** 찍은 숫자는 흘러가고, 딱지는 세어지고 물어진다
- **못 붙인 것만 세면 시도조차 못 한 것이 빠진다.** 1,596건이 그렇게 숨어 있었다
- **모르는 것과 다르게 아는 것은 다르다.** 격리 면제를 세 이유 전부에 걸었다가 2,137→104 로 잘못 떨어뜨렸다 — 동명 부서에 게시판 관리부서를 대신 내주면 틀린 답이 된다
- **묻는 단위가 요점이다.** 1,596건을 글마다 물으면 질문 1,596개, 게시판 단위면 13개
- **승격은 코드가 아니라 "매 실행 재판정"이었다.** 답이 있으면 연결되고 딱지는 저절로 떨어진다
- **전체를 한 번은 끝까지 돌려야 한다.** 부분 실행과 `--check` 로 "통과"를 열 번 말했는데, 유령 직원은 전체를 돌려야만 보였다. 20분이면 되는 일이었다
- **클래스로 잡지 말고 자리로 읽는다.** 보건소 배지의 class 가 pd·yt·ks 로 제각각이었다 — 색 이름이라 뜻이 없다
- **읽는 곳이 다르면 자리도 달라야 한다.** `board_dept` 를 selectors 에 넣었더니 지문이 바뀌어 5시간짜리 재수집을 요구했다
- **값을 만드는 코드가 원천이 준 값을 덮어쓰면 안 된다.** 서브도메인 글의 링크가 전부 죽어 있었다(HTTP 500)
- **LLM 을 쓸지 말지는 "LLM 이라서"가 아니라 넷으로 정한다** — ① 답이 원문에 있나 ② 선택지에 정답이 있나 ③ 틀리면 티가 나나 ④ 검증 축이 있나. 발급처는 셋이 없었다
- **빈칸이 오답보다 낫다. 빈칸은 세어지고 오답은 안 세어진다.** 오늘 잡은 결함이 전부 조용히 들어간 것들이었다

## 한계

- **루프는 돌지만 아직 아무도 답하지 않았다.** `pending.yaml` 의 질문 59개(게시판 13 · 부서명 46)는 사용자 몫이다. 답이 0 이면 루프는 격리 1단계와 같다
- **묻는 단위가 셋뿐이다**(board · dept_name · name). 새 격리 이유가 생기면 `review/01` 에 함수가 하나 더 필요하다 — 선언만으로 안 는다
- **hide 는 status 로 숨긴다.** 숨긴 조직의 직원도 같이 안 보인다(`org.status = 'active'` 필터). 지금 hide 대상 0건이라 안 아프다
- **격리된 채 원천에서 사라진 노드는 quarantined 로 영원히 남는다.** lifecycle 이 active 만 폐지 판정한다. 지금 0건
- **`embedding/03` 배치 500→100** 은 내가 정한 것이다. 호출 11→51번, 몇 초. 되돌리려면 한 줄
- **재수집 날·스케줄러가 안 정해졌다.** 22 · 26 · 1 · A3 나머지 10개가 전부 그날에 묶여 있다
- **답변 축은 여전히 7문항.** 서식 문항 3개는 축을 붙일 수 없었다(서식이 사이트에 없거나, 질문에 서식 낱말이 없다). 45번 질문은 답이 들어온 뒤 gold 에 넣는다 — 지금 넣으면 게이트가 막는다
