## 개념

- **트리거 게이트** — 질문에 특정 낱말이 있을 때만 그 경로를 켜는 것. 점수가 아니라 질문 의도로 가른다
- **자리 보장** — 점수 경쟁에 넣지 않고 후보 한 자리를 확보해 주는 것. 척도가 다른 검색을 섞을 때 쓴다
- **`Board.timeless`** — 그 게시판 글이 오래돼도 유효한가. 서식은 참, 소식은 거짓
- **정답 라벨(gold)** — 질문마다 "무엇이 1위여야 하는가"를 사람이 적어 둔 것. 회귀 기준선과 다르다
- **회귀 기준선(search20)** — "어제와 같은가"만 본다. 어제도 틀렸으면 계속 통과한다
- **후보 정밀도** — LLM 에 준 후보 N건 중 관련 있는 것의 비율

---

## 요약

첨부 서식 검색을 끝내고, **서식 전용 게시판 3개(507건)가 통째로 빠져 있던 것**을 찾아 적재했다. 조직 부류 라벨 940개를 걷어내고 관계 규칙 2개를 넣었다.

가장 큰 것은 마지막에 만든 **검색 품질 측정 도구**다. 그전까지 회귀는 "어제와 같은가"만 봤고, 그래서 `여권 신청 어디서 해`가 오답인 채로 계속 통과하고 있었다. 정답 라벨 26문항을 만들고 재니 **1위 적중 14/16**이었고, 원인 셋을 고쳐 **16/16**이 됐다.

그 과정에서 **가설 9개를 세워 전부 기각당했다.** 측정 도구 없이 "잡음을 줄이면 좋아질 것"이라는 전제로 세운 것들이었고, 도구를 만든 뒤에는 세 처방이 한 번에 맞았다.

## 1. 첨부 서식 — 점수가 아니라 질문 의도가 갈림선이었다

##### 문제
게시글 첨부 3,291개를 적재해 놓고 검색이 쓰지 않았다. 붙였더니 세 가지가 망가졌다.

```
엉뚱한 파일    "자동차세 납부 기한" -> 자동차세 홍보안내문
있는데 못 찾음  "장애인 특별공급 신청 서류" -> 0건
없는데 억지로   "자원봉사 확인서 양식" -> 재활용품 매각 계약서
```

##### 원인과 처방 넷

**① 트리거 게이트.** 점수로는 못 가른다. 관계로 좁히고 보도자료를 빼도 오탐이 남는데 전부 "서식을 찾는 질문이 아닌데" 관련 홍보물이 딸려온 것이었다 — `자동차세 납부 기한` -> 홍보안내문 10.5, `여권 신청 어디서 해` -> 수수료 포스터 4.5. **파일 쪽 점수가 아니라 질문 쪽 의도가 갈림선**이라, 질문에 `서식·양식·신청서·서류` 같은 말이 없으면 아예 조회하지 않는다.

기준선 20문항 오탐이 **4건 -> 0건**이 됐다.

**② 순회를 자식 한 칸까지.** 시민이 아는 이름은 '과'인데 글을 올리는 건 그 밑 '팀'이다.

```
검색이 간 곳    장애인복지과
파일 올린 곳    발달장애인지원팀 -> 장애인복지과      바로 그 밑 자식
```

`employees_for` 가 부서 직원을 셀 때 `PART_OF` 한 칸을 같이 보는 것과 같은 확장이다.

**③ 임계 3 -> 5.** 자식 확장 뒤 시민 표현 12건을 상위 3건까지 눈으로 봤다.

```
6점 이상   중고PC 8.2 · 장애인 특별공급 6.7 · 어린이집 8.1 · 일자리 19.4    전부 정답
5점대      전기차 -> 조기폐차 보조금 공고 5.8                              부서·주제 맞음
4점 이하   청년기본소득 -> 청소년예술제 단체신청 4.4 ·
           자원봉사 -> 재활용품 매각 계약서 3.2                            전부 오답
```

4점 이하가 전부 오답인 이유는 그 질문에 맞는 파일이 **아예 없기** 때문이다. 후보가 비면 BM25 는 남은 것 중 제일 나은 쓰레기를 준다. **임계는 "없으면 없다고 답하게" 만드는 장치다.**

**④ 전역 경로를 합친다.** 파일명이 질문어를 통째로 담으면 관계 없이도 정답이다 — `대관허가신청서 등.hwp` 18.5. 파일을 올린 전시운영팀은 미술관정책과 소속이라 검색이 간 주차관리팀(첨단교통과)과 나무가 완전히 다르다. 순회로는 어떻게 넓혀도 못 닿는다.

임계 15의 근거: 트리거를 통과하지만 첨부가 답이 아닌 질문 10건의 전역 1위 점수를 재니 최고가 9.0 이었다.

##### 설계 결함 하나
처음에는 `if not rows` 로 "관계가 아무것도 못 찾았을 때만" 전역을 돌렸다. 그랬더니 `지방소득세 환급청구서` 가 관계로 10.6짜리를 먼저 물어서, 전역에 있는 20.4짜리 정답이 영영 안 나왔다. **관계가 뭔가 찾았다는 것이 그것이 최선이라는 뜻은 아니다.** 둘을 합치고 점수로 세운다.

##### 블록 지시문이 LLM 에게 게이트를 다시 시키고 있었다
지시문이 `"질문이 서식·양식을 찾는 것일 때만 안내하라"` 였다. 그건 트리거 게이트가 없던 시절 LLM 이 게이트 노릇을 하던 흔적인데, 그대로 남아 있으니 **답을 손에 쥐고도 안 줬다.**

```
"출생신고 서류 뭐 필요해"
  받은 후보  출생신고서(1).hwp  10.9
  실제 답변  "출생신고에 대한 구체적인 서류 목록이 포함되어 있지 않습니다"
```

판정 기준을 '질문의 종류'에서 **'파일이 질문 내용과 맞는가'**로 옮겼다. 걸러야 할 것은 질문 종류가 아니라 딸려온 홍보물이다.

##### 결과
답변에 다운로드 주소가 실리는가, 각 질문 3회 반복: **18/18 의도대로.**

```
출생신고 서류 뭐 필요해   3/3 등장     혼인신고 할 때 서류    3/3
자동차 등록 신청서 어디   3/3          중고PC 신청서         3/3
여권 발급 구비서류       0/3 (막힘)   기초생활수급 신청 서류  0/3 (막힘)
```

## 2. 서식 전용 게시판이 통째로 빠져 있었다

##### 문제
`청년기본소득 신청 서식`·`자원봉사 확인서 양식` 이 안 잡혔다. 처음에는 "시민 서식은 민원 안내 페이지에 있다"고 단정했는데, **근거 없이 말한 것이었다.**

##### 실측 — 민원 페이지에는 첨부 필드가 아예 없다

```
민원 644건의 파일 관련 필드   없음
본문·필드에 파일 흔적          0건
```

크롤러가 첨부 자리를 안 봤으니 있는지조차 모르는 상태였다. 페이지를 직접 열어 보니 `fileDownload` 가 **JS 블록**에 있고 주석이 `<!-- 본문 첨부파일 다운로드 경로 수정 -->` 였다 — 링크를 브라우저가 실행 중에 바꾼다. 정적 HTML 만 보는 크롤러는 못 본다. 표본 18건 중 3건이 본문에 파일을 갖고 있었다.

##### 진짜 원인 — 서식 전용 게시판 3개를 안 긁고 있었다

```
1026  민원서식자료실       469건   2018-02-22 ~ 2026-08-30   담당부서 칸 O
1298  민원서식             26건   2017-06-08 ~ 2026-04-08   담당부서 칸 X (작성자명)
1275  옥외광고물 관련서식    12건   등록일 칸 X               담당부서 칸 O
                        ─────
                          507건
```

첫 페이지만 봐도 `효도수당지원신청서`·`위임장`·`가로등 이설 신청서` — 정확히 못 잡던 종류다.

##### 넷을 안 고쳤으면 적재해도 안 보였다

```
게시판별 기준일    DAYS=365 를 전 게시판에 걸면 469건 중 대부분이 잘린다.
                 서식은 2018년 것도 지금 쓰는 서식이다
등록일 없는 게시판  1275 는 등록일 칸이 아예 없어 파서가 전 행을 버렸다.
                 seq 가 작성 시각이라(20250702101111788) 앞 8자리로 날짜를 만든다
담당부서 폴백      1298 은 목록에 부서가 없어 dept_name=None 이 되고 영영 안 붙는다
Board.timeless    검색의 ATTACH_DAYS=365 가 그대로면 적재해도 469건이 안 보인다.
                 게시판의 시간 성격을 Board 노드에 실어 검색이 읽게 한다
```

`timeless` 값은 크롤러 `BOARDS` 의 `days=None` 에서 온다. 두 곳에 따로 적으면 한쪽만 고쳐진다.

##### 1298 은 부서를 안 붙였다
상세 하단 '담당자 정보'에 담당부서가 있지만 6건을 재 보니 **가로등 이설·건설업·제한차량 신청서가 전부 '경제자유구역추진단' 하나로 같았다.** 글쓴이가 아니라 게시판 운영부서다. 그걸 쓰면 틀린 사실이 들어간다. 안 거는 편이 낫다.

##### 1026 도 469건 중 273건만 연결됐다
나머지는 `의약무관리팀`(4개 구 보건소)·`시세팀`(4개 구)처럼 **동명 조직**이라 어느 구인지 못 가른다. 1026 은 전화번호가 0건이라 기존 전화 폴백도 못 쓴다. 장안구 서식을 팔달구에 붙이면 틀린 사실이므로 안 붙인다.

##### 동명 문제는 풀어도 소용없다는 것도 확인했다

```
지방소득세 환급청구서   검색은 지방소득세팀 -> 파일은 시세팀
위임장 양식           검색은 '신청서 양식'(민원) -> 종합민원팀
                     검색 후보와 파일 부서명 겹침 0
```

모호해서 못 붙는 게 아니라 **검색이 애초에 다른 조직에 내려앉는다.** 동명 4개 중 하나를 골라 줘도 그 조직이 후보에 없다.

##### 결과
`Article 3,252 -> 3,771` / `Attachment 3,291 -> 4,204` / `POSTED_BY 3,061 -> 3,346`.

##### 함정 세트가 무효가 됐다
서식이 없을 때 만든 "구비서류 질문에 첨부는 답이 아니다"라는 전제가 깨졌다.

```
출생신고 서류 뭐 필요해   -> 출생신고서(1).hwp            10.9   정답
혼인신고 할 때 서류      -> 혼인신고서(0).hwp            11.3   정답
자동차 등록 신청서 어디   -> 자동차 신규등록 신청서.hwp     10.1   정답
인감증명서 발급 서류     -> 인감증명서 발급 사실 통보 신청서 14.4   정답
```

진짜 오탐은 여권 포스터·기초생활 리플릿 2건뿐이고 적재 전과 같다.

## 3. 조직 부류 라벨을 걷어냈다

##### 문제 제기
`:총괄기관`·`:실무조직` 라벨이 꼭 필요한가.

##### 실측

```
쓰는 곳   nodes/01_org_units.py 가 붙임        쓰기만
읽는 곳   없음. 검색·라우터·검증 어디에서도 (o:실무조직) 을 안 씀
```

그리고 `unit_level` 이 상위호환이다.

```
MATCH (o:총괄기관)                                          21
MATCH (o:OrgUnit) WHERE o.unit_level IN [총괄 7종]          21   인덱스 있음
```

같은 답인데 `unit_level` 쪽은 "국만"·"구만"도 물을 수 있다. 라벨은 7종을 하나로 뭉갠 **정보를 잃은 파생 뷰**다.

##### 선언과 라벨은 다르다
처음에 이 둘을 뭉뚱그렸다. `org_classes` 선언 자체에는 살아 있는 소비자가 있다 — `schema.py:47` 이 그걸 **unit_level 닫힌 어휘 대장**으로 써서 `bureau_levels` 오타를 잡는다. **선언은 일하고 있고, 노드에 붙는 라벨만 아무도 안 읽는다.**

##### 소관 축은 부류를 가로지른다

```
bureau_levels 7종   국·실·구·의회사무국·지방의회   총괄기관
                    사업소·직속기관                실무조직   <- 넘어감
```

`:총괄기관` 으로 소관을 물을 수 없다. 두 축이 직교라 라벨이 대신 못 선다.

##### 라벨에는 결함도 있었다
`nodes/01` 은 `SET n:실무조직` 만 하고 `REMOVE` 를 안 한다. 개편으로 과가 국이 되면 두 라벨이 함께 남는다. **선언은 disjoint 를 강제하는데(schema.py 가 sys.exit 까지 한다) 적재는 그걸 안 지켰다.** 겹침 0은 보장이 아니라 우연이었다.

##### 결과
`:총괄기관` 21 · `:실무조직` 919 제거. `OrgUnit 940 · Entity 5,911` 변동 없음, 회귀 이상 없음.

## 4. 관계 규칙 둘 — 0건일 때 넣어야 한다

##### 만든 것

```
DEPT_NOT_BODY       민원의 담당부서는 실무조직이어야 한다     validate/01 마커
PART_OF_DIRECTION   총괄기관은 실무조직 밑에 오지 않는다      위반이면 중단
```

##### 도입 시점 위반 0

```
HANDLED_BY 대상 700건   과 608 · 단 46 · 팀 18 · 직속기관 12 · 시설 9 · 관 6 · 사업소 1
PART_OF 방향 938건      실무->총괄만 있고 반대는 0
```

**0건일 때 넣는 것이 요점이다.** 나중에 넣으면 이미 쌓인 위반이 무더기로 떠서 진짜 새 위반이 그 안에 묻힌다.

##### 왜 방향 규칙은 중단인가
`IN_CHARGE_BUREAU` 는 `PART_OF*0..5` 로 가장 가까운 총괄 조상을 찾는다. 나무가 한 군데 뒤집히면 **583건이 한꺼번에 엉뚱한 국을 가리키는데 답이 그럴듯해서 아무도 알아채지 못한다.** 그 상태로 embedding 까지 돌면 틀린 소관이 검색 결과에 실린다.

`main.py` 순서가 유리하다 — `validate/01`(76) -> `relationships/05`(77) -> `embedding/01`(79). 추론과 임베딩 전에 멈춘다.

##### 규칙을 일부러 깨뜨려 검증했다
한 번도 안 걸려 본 규칙은 쿼리가 틀렸어도 0을 낸다. 시험용 노드를 매달아 보니 둘 다 잡혔고, 치우니 0으로 복귀했다.

## 5. 브리지에서 첨부가 사라지고 있었다

##### 문제
로컬에서 18/18 로 확인한 첨부가 **Chatty 브리지를 통과하면 하나도 안 나왔다.**

##### 원인
브리지는 `context_blocks` 와 `hits` 가 1:1 순서라고 가정한다(주석에도 그렇게 적혀 있다). 그런데 첨부 블록만 그 루프 뒤에 붙어서 짝이 없다.

```
엉뚱한 hit 이름이 제목으로 달림
항상 마지막이라 max_items=3 컷에 먼저 잘림
```

##### 왜 조용했나
로컬 시험은 `make_answer=True` 로 **KG 자체 LLM** 을 썼다. 브리지는 `make_answer=False` 로 근거만 받아 Chatty LLM 이 답을 만든다. **그 경로를 한 번도 안 쟀다.**

##### 택한 안
첨부를 경쟁에서 빼고 맨 앞자리를 준다. Chatty 자신도 첨부에서 같은 문제를 겪고 같은 방식으로 풀었다 — `app.py:3104` "첨부 chunk는 일반 검색 결과와 같은 풀에서 경쟁시키지 않는다."

`ATTACH_GUARD` 를 따로 뒀다. 기존 `VECTOR_GUARD` 가 "여기서 유추하지 마라"라서 그걸 붙이면 LLM 이 링크까지 안 쓰고 넘어간다. 첨부는 유사도 후보가 아니라 실물 파일이라 성격이 반대다.

##### 결과 (브리지 통과 실제 답변)

```
출생신고 서류        8.6s   출생신고서 다운로드 + 2025-01-14
효도수당 신청서       7.3s   [별지 제1호서식] + 게시일 + 구비서류 + 문의처
지방소득세 환급청구서   8.7s   세 판(2018·2022·2023)을 게시일과 함께
여권 발급 구비서류     7.7s   포스터 안 나감
```

부수 효과로 **출생신고 답이 정확해졌다.** 첨부가 1번 자리에 들어가면서 LLM 이 그걸 기준으로 답을 세웠다 — 전에는 출산지원금 서류를 나열하고 "분만일로부터 6개월 이내"라고 틀렸다.

## 6. 검색 측정 기반 — 오늘의 본론

##### 문제
회귀 기준선(`search20.json`)은 "어제와 같은가"만 본다. **어제도 틀렸으면 계속 통과한다.**

실제로 회귀 20/20 을 통과하면서 `출생신고 서류 뭐 필요해` 의 후보 5건이 전부 무관했고, `여권 신청 어디서 해` 가 오답인 채로 굳어 있었다.

##### 만든 것

```
data/baseline/gold.json      정답 라벨 26문항
   top1      1위로 나와야 하는 것 하나. 여럿이 타당하면 null
   relevant  후보로 들어와도 좋은 것 전부
   attach    서식이 답의 일부인 질문
   note      판정 근거

validate/04_retrieval.py     1위 적중 · 후보 정밀도 · 첨부 적중 · 경로별 집계
```

##### 라벨 자체를 검산하게 만들었다
`gold.json` 의 이름이 그래프에 없으면 멈춘다. 첫 실행에서 바로 일했다 — `냉장고` 를 "그래프에 없다"고 판정했는데, 대형폐기물 요금은 `WasteItem` 노드에 있고 내 검산 쿼리가 `CivilService`·`OrgUnit` 만 보고 있었다. **도구가 맞고 쿼리가 좁았다.**

##### 라벨이 두 번 틀렸다
부서 답을 오답으로 세고 있었다. `전입신고`·`민방위`·`전기차` 는 민원 페이지와 담당 부서 둘 다 1위로 타당한데 민원만 정답으로 박아 놨다. `대형폐기물 냉장고` 는 가격표 페이지가 아니라 품목 노드가 답이었다.

1위 적중이 13/19 -> 14/16 이 된 것은 **채점 기준이 틀렸던 것이지 검색이 좋아진 게 아니다.**

## 7. 검색 오답 셋을 고쳤다

##### `LEXICAL_MIN = 14`
BM25 는 후보가 없어도 남은 것 중 제일 나은 것을 내놓는다. 검증 없이 1번 자리에 앉히면 오답이 정답을 밀어낸다.

```
자리보장이 구해낸 것    1건
벡터도 이미 찾은 것    12건
오답을 1위에 앉힌 것   13건
```

임계별로 재니 14 에서 정답 손실 0으로 오답 4건이 걸러졌다(CCTV 12.9 -> 불법주정차 사전알리미, 누수 7.1 -> 지표투과레이더탐사, 급수팀 총괄 4.2 -> 도로제설, 감사관 3.1 -> 구제제도 안내). 16 부터는 정답을 잃는다.

##### 의문사 제거
`"여권 신청 어디서 해"` 의 `"어디서"` 가 `어디서나민원(FAX민원)` 과 물려 32.4점 1위를 먹었다.

**어절 전체가 일치할 때만 뺀다.** 부분 문자열로 지우면 기준선의 `어디서나FAX민원이 뭐야` 가 깨진다.

서술어(`있어`·`해`·`필요해`)까지 넣었다가 걷어냈다 — `"청년 관련 정책 뭐가 있어"` 에서 `있어` 를 빼니 1위가 `청년 주거 패키지 지원`(정답)에서 `관련사이트`(오답)로 바뀌었다. 서술어도 BM25 점수에 기여하고 있었다.

##### 조직명 완전일치 승격
시민이 이름을 그대로 불렀으면 유사도로 겨룰 일이 아니다.

```
"장안구보건소 어디에 있어"   1위 보건소 취약계층 건강 지원 (어휘 47.8)
                          2위 장안구보건소            주소를 가진 쪽
```

긴 이름 우선(`장안구보건소` > `장안구`), 3글자 미만 제외. 발동 4건 전부 정답, 오탐 0. **실제로 순위를 바꾼 것은 장안구보건소 하나**다 — 감사관·급수팀은 이미 1위였고, 제1부시장은 리더 숏컷이 앞에서 가로챈다.

##### 결과

```
            시작    임계    의문사   이름일치
1위 적중    14/16   14/16   15/16   16/16
정밀도       35%     35%     35%     35%
```

회귀에서 바뀐 2건이 정확히 고치려던 2건이고 둘 다 오답 -> 정답이다.

## 8. 기각된 가설 아홉

측정 도구 없이 "잡음을 줄이면 좋아질 것"이라는 전제로 세운 것들이고 **전부 틀렸다.**

```
기본 민원이 빠졌다        사이트 메뉴 커버리지 96%. 출생신고는 대법원 소관이라 시가 안내 안 함
긴 문서가 잡음이다        묶음 페이지는 '복지·문화' 1개뿐. 나머지는 한 주제인데 긴 안내문
허브 문서가 있다          26문항 후보 118종 중 101종이 1회 등장. 반복 상위는 조직 노드
A 코사인 뭉침            1~10위 폭 중앙값 0.0526. 균일하게 좁지 않음
B 임베딩 어긋남           정답이 벡터 60위 안 100% · 1위 13/25 · 5위 안 23/25
C 후보 수 과다            2건으로 줄이면 정밀도 42%인데 정답을 통째로 잃는 질문 8건
상대 임계가 낫다          고정 N 보다 모든 구간에서 나쁨. 폭이 좁은 질문이 8건을 그대로 유지
부피로는 더 나쁘다        건수 35% vs 부피 33%. 차이 없음
길이 상한이 답            정답 블록 평균 1,300자 vs 오답 1,396자. 분포가 겹쳐 둘 다 깎임
표를 임베딩에서 빼기       70건 재임베딩 시뮬레이션: 좋아짐 0 · 나빠짐 1
```

##### 공통 원인
전부 **한 사례를 보고 일반화**했다. `출생신고` 하나가 21,048자에 정답이 2% 였던 걸 보고 "부피가 문제"라고 했는데, 26문항을 다 재니 33% vs 35% 였다.

##### 반면 실제로 먹힌 셋은
전부 **구체적인 오답 하나를 보고 그 원인을 좁힌 것**이었다. `여권 신청` 이 왜 FAX민원으로 가는지, `장안구보건소` 가 왜 2위인지.

##### 그래서 얻은 판단
**후보 정밀도 35%는 이 시스템의 정상 상태다.** LLM 이 후보를 걸러 내는 것이 설계의 일부고, 답이 깨지는 것은 정밀도가 극단(0/5)일 때뿐이다.

```
수도계량기  2/5  답변 정확
민방위      3/5  답변 정확 (과태료 10만원 · 거주지 관할까지)
출생신고    0/5  답변 나쁨
```

개선은 "잡음 줄이기"가 아니라 **"틀린 1위 찾아 고치기"** 로 가야 한다. `validate/04` 가 그걸 잡는 도구다.

## 9. 기준선을 재현 가능하게 만들었다

`validate/03_baseline.py` 신설. 손으로 뜨면 무엇을 어떻게 셌는지가 남지 않는다 — 인덱스 DDL 을 `schema/01` 한 곳에 모은 것과 같은 이유다.

옛 기준선 버그도 하나 고쳤다. `sources.org_live.records` 가 0 이었는데, 리스트가 아니라 `{"orgs": [...]}` 라서 `len()` 이 키 개수를 셌다. **0 은 "없음"과 "안 셌음"이 구별되지 않는다.**

없어진 `org_classes` 자리에 `unit_levels` 를 넣었다. 라벨이 20/919 로 뭉갰던 것이 17종으로 보인다.

## 재사용 가능한 판단

- **임계는 "없으면 없다고 답하게" 만드는 장치다.** 후보가 비면 BM25 는 남은 것 중 제일 나은 쓰레기를 준다
- **점수로 못 가르는 것을 질문 의도로 가른다.** 트리거 게이트가 기준선 오탐 4건을 0으로 만들었다
- **관계가 뭔가 찾았다는 것이 그것이 최선이라는 뜻은 아니다.** 경로를 합치고 점수로 세운다
- **지시문이 앞 단계와 중복되면 LLM 이 답을 쥐고도 안 준다.** 게이트가 생겼으면 지시문에서 게이트를 빼야 한다
- **선언과 그 선언이 만드는 라벨은 다르다.** 라벨을 걷어내도 선언은 계속 일할 수 있다
- **0건일 때 규칙을 넣어야 한다.** 나중에 넣으면 쌓인 위반에 새 위반이 묻힌다
- **한 번도 안 걸려 본 규칙은 일부러 깨뜨려 봐야 한다.** 쿼리가 틀렸어도 0을 낸다
- **"어제와 같은가"는 품질이 아니다.** 정답 라벨이 없으면 안정적으로 틀린 것을 통과라고 부른다
- **한 사례로 일반화하지 않는다.** 오늘 아홉 번 그렇게 틀렸다
- **모르는 채로 거는 것보다 안 거는 편이 낫다.** 1298 의 26건, 1026 의 196건을 안 붙였다

## 한계

- **후보 정밀도 35%** 는 개선하지 못했다. 여덟 가지 방법이 전부 실패했고, 그것이 답변 품질에 큰 영향을 안 준다는 것만 확인했다
- **`main.py` 클린 실행 미검증.** `nodes/01` 이중 중괄호는 `EXPLAIN` 으로만 확인했고 28단계가 순서대로 도는 것은 못 봤다
- **1026 의 469건 중 196건이 조직에 안 붙었다.** 동명 조직(4개 구 보건소·시세팀)이라 못 가른다
- **`dept_name='yes종합민원팀'`** 1건. 파싱 찌꺼기라 위임장 서식이 연결 안 된다
- **`Article` 생애주기 없음.** `lifecycle/01` 이 Article 을 안 봐서 1년 창 밖으로 나간 글이 표시 없이 남는다(현재 21건)
- **`hybrid` 가 `kg` 대비 값이 있는 질문이 몇 개인지 안 쟀다.** 2배 느린데(7.3s vs 14~23s) 근거가 없다
- **직원 이름이 5,084명 중 6명뿐.** "급수팀 총괄이 누구야"에 이름을 못 댄다
