## 1. 검색: 벡터 단독 → 하이브리드

### 문제

제목을 **그대로** 물어도 자기 노드를 못 찾는 일이 있었다. `맞춤형 기초생활보장제도`를 검색하면 자기 자신이 4위(0.6906)로, 무관한 `미세먼지 계절관리제`(0.6917)보다 아래였다. 원인은 희석이다 — 본문 1,885자를 벡터 하나로 뭉개면 제목처럼 짧고 결정적인 신호가 묻힌다.

40개 표본(제목을 그대로 질문)으로 재보니 **top1 68% / top5 80%**였다.

### 시도와 결과

| 방안 | top1 | 판정 |
|---|---|---|
| 벡터 단독(baseline) | 68% | — |
| 임베딩 텍스트에 제목 3회 반복 | 77% | 효과 미미 |
| **벡터 + 어휘(fulltext) 병행** | **90%** | 채택 |

어휘 인덱스는 `cjk` 애널라이저가 필수였다. 기본(standard) 애널라이저는 한글 복합어를 통짜 토큰으로 봐서 `기초생활수급자 신청`이 `맞춤형 기초생활보장제도`를 **0건** 매칭했다. cjk는 2글자 바이그램으로 쪼개 색인하므로 15.2점 1위로 잡는다. 이 판단은 새로 한 게 아니라 코드베이스에 이미 있던 선례(`employee_duty_index`)를 따른 것이다.

### 점수 척도가 다르면 섞어 정렬할 수 없다

BM25(~15)와 코사인(~0.7)은 척도가 달라 한 리스트에 넣고 정렬하면 어휘 쪽이 무조건 이긴다. 그래서 **"상위 N건은 후보에서 자르지 않는다"**로만 썼다(별칭 승격과 같은 방식).

N을 정하는 데 실측이 필요했다. cjk 바이그램은 글자만 겹쳐도 매칭되기 때문이다:

```
"전입신고 어디서 해"        → '어디서나민원'   9.9   (어디서)
"정자동 행정복지센터 전화번호" → '수원시 외국인복지센터' 12.8  (복지센터)
```

진짜 일치와 이런 우연을 **점수로 가르려다 실패했다**. 절대 점수 분포가 겹치고(정답 최소 3.4 / 무관 9.9), 1·2위 격차 비율도 겹친다(정답 `기초생활` 1.20 < 무관 `전입신고` 1.32). 걸러내는 걸 포기하고 **잠식 폭을 1자리로 묶는 쪽**으로 갔다 — 무관한 후보 1개가 섞여도 나머지 4자리로 답이 나온다.

| 보존 개수 | top1 | top5 | 부작용 |
|---|---|---|---|
| 2건 | 92% | 100% | 전입신고·정자동 답변 깨짐 |
| **1건** | **90%** | **100%** | 없음 |

top1을 1건 손해 보고 회귀를 막는 쪽을 택했다.

### 별칭 사전을 어휘 검색에도 연결

별칭 사전(시민어 → 행정어)이 벡터 검색에만 쓰이고 어휘 검색엔 질문 원문만 넘어가고 있었다. 정작 어휘 인덱스에 들어 있는 건 행정어 쪽인데. 연결하니 `재산세 안 내면 어떻게 돼`가 `세금납부를 제때하지 않으면`을 1위로 잡아 납부지연가산세를 정확히 답한다(전엔 못 찾던 페이지).

### 별칭 사전에 제재·불이행 범주가 통째로 비어 있었다

`민방위 교육 안 가면 어떻게 돼`가 실패했는데, 원문에 `불참자 과태료 부과` 페이지가 **있는데도** 못 찾은 것이었다. 데이터 공백이 아니라 어휘 문제:

```
"민방위 교육 불참 과태료"  →  1위 (0.7549)   행정어
"민방위 교육 빠지면 벌금"  → 52위 (0.6764)
"민방위 교육 안 가면 …"    → 96위 (0.6559)   시민어
```

범주 단위로 채웠다(벌금→과태료, 안 가면/빠지면→불참, 안 내면/미납→체납·가산금, 어기면→위반). `빠지면 벌금` 52→2위, `안 가면` 96→12위.

## 2. 답변: 껍데기 페이지에서의 환각

본문이 제목 한 줄뿐인 페이지가 37건 있다(실제 내용은 첨부 PDF나 링크에). 이런 후보가 정상 후보와 똑같은 모양으로 컨텍스트에 들어가니 LLM이 빈칸을 자기 사전지식으로 메웠다.

```
기후위기 적응대책   본문 17자: "수원시 제3차 기후위기 적응대책"
  → 답변: "기후위기로 인한 피해를 최소화하고 건강·재해·생태계의 회복력을 높이는…"  ← 원문에 없음

상하수도란?         본문 80자: "자세한 사항은 상수도사업소 홈페이지 참고"
  → 답변: "상수도와 하수도를 포함하는 개념으로, 물의 공급과 배수를 관리하는 시스템"  ← 원문에 없음
```

`SYSTEM_PROMPT`에 "지어내지 마라"가 이미 있는데도 뚫렸다. **staleness와 같은 처리**로 해결했다 — 판단은 코드가 하고(제목·별칭 뺀 본문 길이), LLM에겐 해당 후보 줄에 붙은 지시만 넘긴다.

부작용이 하나 있었다: 지시를 길게 풀어 썼더니 **LLM이 그 문장을 답변에 그대로 옮겼다**(`수원델타플렉스관리기본계획` 답변에 "위 본문에 적힌 문장 외에 이 주제에 대한 일반 지식은 포함되어 있지 않습니다"가 노출). 짧은 명령형으로 줄이고 "이 지시는 답변에 옮겨 적지 말 것"을 명시해 해결.

본문으로 답할 수 있는 짧은 페이지(`소화기 사용법` 80자)까지 걸려도 무해하다 — 이 지시는 본문 기반 답변을 막지 않고 본문 밖 지식 추가만 막는다.

## 3. 법령 노드화

`regulation_text` 문자열(`"도로교통법 제32조; 주차장법 제6조"`)을 파싱해 `(:Regulation)` + `BASED_ON`으로 세웠다. 조항은 노드가 아니라 **관계 속성**에 둔다 — 조항이 달라도 같은 법령으로 묶여야 "도로교통법에 근거한 민원 전부"가 성립한다.

### 파싱 방식 전환

처음엔 구분자(`;` `,` `및`)로 자른 뒤 파싱했는데 76%에서 막혔다. `,`·`및`·`·`가 법령명 **안에** 워낙 자주 들어 있어서, 자르는 순간 `"도로교통법 (정차 또는 주차의 방법"` 같은 조각이 법령명이 됐다. **"자르고 파싱"이 아니라 "꼬리표(법/조례/시행령…)를 직접 찾는"** 방식으로 바꿔 99.3%.

### 파싱 오류 7종 (원인이 전부 달랐다)

| 잘못된 이름 | 원인 | 수정 |
|---|---|---|
| `29이태원…`, `18민주유공자…` | 문자클래스에 `.` 없음 → `10.29`, `5.18` 앞자리 잘림 | `.`·`-` 추가 |
| `제29조(사용료율과…` | 반각 낫표 `｢｣` 미포함 → 조문 제목이 법령명으로 | `｢｣` 추가 + 조문 시작 이름 거부 |
| `법률 제3719호「특정건축물…` | 공포번호 접두어가 눌어붙음 | 접두어 제거 |
| `141호(휘발성유기화합물…)고시` | 최소매칭이 "환경부 고시"에서 끊김 | 꼬리표 뒤 공포번호면 이름 안 끝난 것으로 |
| `시 조례`, `시행규칙` | 지시어·미해결 시행령이 노드가 됨 | 일반명사 목록 확장 + 기준 법령 없으면 버림 |

덤으로 `｢국유재산법｣제30조`처럼 닫는 낫표가 조항 앞에 오면 조항을 통째로 놓치고 있었다 — **조항 파싱 205 → 218건**.

## 4. 수수료와 지원금은 방향이 반대인 두 개념이다

### 문제

추출 스키마에 금액 칸이 `fee_text`(시민이 **내는** 돈) 하나뿐이었다. 그러니 지원사업 페이지의 "지원내용/지원금액"이 **유일한 금액 필드로 밀려 들어왔다**.

```
난임부부 시술비 지원      30만원  ← 지원금인데 수수료로 적재
경기도 산후조리비 지원     50만원  ← 지원금
고위험 임산부 의료비 지원  300만원  ← 지원금
마을기업                  1억원  ← 지원금
```

이 상태로 `수수료 3만원 이상인 민원`을 물으면 **지원사업을 수수료인 것처럼 45건 답했다.**

프롬프트 문구 문제가 아니라 **스키마 공백**이었다. 담을 칸이 없으면 값은 옆 칸으로 샌다.

### 해결: 2단계

**1단계 — 방향 분류 후 이동.** 같은 문장을 방향에 맞는 칸으로 보내면 재추출이 필요 없다.

```
pay      → fee_text 유지     + fee_min/fee_max
receive  → benefit_text 이동  + benefit_min/benefit_max, fee_text 비움
mixed    → fee_text 유지, 숫자 파생 안 함 (본인부담금·지원금이 한 문장에 섞임)
```

**2단계 — 추출 단계에서 직접.** 1단계는 *이미 fee_text에 들어간 것만* 고칠 수 있다. 애초에 어느 칸에도 안 담긴 지원금은 못 잡는다. 별도 추출 패스로 직접 뽑으니 **34건 → 117건**.

### 결과

```
fee_text        114 → 80건 (수수료만)
지원금          34 → 117건 (금액 파생 92건)
수수료 3만원 이상  45건 → 19건   (과태료·검사료·여권 수수료만)
수수료 있는 민원  111건 → 79건
지원금 100만원 이상  (불가) → 26건
```

답변 라벨도 갈렸다. 전엔 `수수료: 출생아 1인당 50만원 지원`으로 컨텍스트에 실렸다 — 본문에 '지원'이라 적혀 있어 답변까지 뒤집히진 않았지만, `아동수당 10만원`처럼 본문 단서가 없으면 뒤집힐 수 있는 상태였다.

## 5. 신청 채널 노드화

### 문제

`온라인으로 신청할 수 있는 민원 전부`를 물으면 벡터검색이 **자동차 등록 페이지 한 장**을 찾아 그 안의 목록을 전수인 양 답했다. 유사도 매칭으로는 집합 연산을 표현할 수 없다.

`procedure_text`는 채널 목록이 아니라 처리 흐름 서술이라(`"본인직접 방문신고 > 본인여부 확인 > …"`) 정규식으로는 못 뽑는다 — 118건에 채널어가 있지만 78건은 2개 이상이 문장 속에 섞여 있다.

### 결과

```
(:CivilService)-[:AVAILABLE_VIA]->(:Channel {name})
Channel 10종 / AVAILABLE_VIA 376건 (239개 민원)

방문 187 · 온라인 92 · 전화 32 · 우편 15 · 정부24 15
팩스 12 · 이메일 9 · 위택스 8 · 모바일앱 4 · 무인민원발급기 2
```

```
온라인으로 신청 가능한 민원  →  88건   (전: 한 페이지 안의 13건)
정부24에서 되는 민원        →  15건
위택스로 되는 민원           →   7건
```

개별 답변에도 `신청 경로:` 줄이 붙는다 — `등초본 발급 어디서 해` → "무인민원발급기, 방문, 정부24".

## 노드 vs 속성 판단 기준

이번에 두 번 갈렸다. 기준은 **① 여러 부모가 현실의 같은 실체를 가리키는가 ② 그 실체에 붙일 독립된 사실이 있는가** — 둘 다여야 노드다.

| 대상 | ① 공유 | ② 독립 사실 | 판정 |
|---|---|---|---|
| 서류 `주민등록등본` | 27개 민원 | 서류 종류 자체 | 노드 |
| 법령 `도로교통법` | 여러 민원 | 조항·법령 정보 | 노드 |
| **채널 `정부24`** | 15개 민원 | 그 사이트 하나 | **노드** |
| **금액 `40,000원`** | 7개 민원이 갖지만 검사료·과태료·견인료로 **서로 다른 돈** | 없음 | **속성** |
| 분야 `복지` | 147개 민원 | 이름밖에 없음 | 속성 |
| 외부기관 `고용노동부` | 3개 민원 | 대표번호 1350(중복 3행뿐) | 속성 (지금은) |

금액을 노드로 묶으면 "이 셋이 같은 요금"이라는 **거짓 사실이 그래프에 생긴다**. 민원마다 노드를 만들면 1:1이라 홉만 늘고 공유·새 사실이 0이다.

> 다만 수수료는 36건이 조건부 다단계다(면적 구간별 4단계, 톤수별, 여권 면수·기간별). `min/max`는 이걸 요약한 것이라 "500㎡ 건물 사용전검사 수수료"에는 구조로 답할 수 없다. 필요해지면 `(:FeeTier {condition, amount})`로 올리는 게 맞다 — 그건 `min/max`보다 엄밀히 표현력이 크다.

## 그 밖에 고친 것

| 문제 | 원인 | 수정 |
|---|---|---|
| 동명 민원이 컨텍스트 잠식 — `새희망 일자리` 3건이 top5 중 4자리, `아동수당` 3자리 | 동명 접기 조건이 `peer_count > 1`이라 조직에만 걸림. 민원은 홈페이지가 같은 사업을 여러 탭에 올린 중복 | `(이름, 분야)`가 같을 때만 접음 — 이름만으로 접으면 세금/교통 `인터넷납부`처럼 정당한 동명이 사라짐 |
| `동 행정복지센터에서 처리하는 민원 목록` → 44개 동 이름 반환 | 토큰 `동`이 조직 라우터에 먼저 걸림 | **"민원을 나열해달라는 질문에 조직 목록 라우터는 답하지 않는다"** — 걸 축이 없으면 벡터로 흘려보냄 |
| 위 수정 후 `행정복지센터`의 '복지'가 분야로 오매칭 → 141건 반환 | `_longest_match`가 부분 문자열 매칭 | 앞 글자가 한글이면 더 긴 낱말의 일부로 보고 제외. 뒤 글자는 안 봄(조사가 걸림) |
| `고용노동부가 담당하는 민원 목록` → 수원시 노동일자리정책과 담당 '노동상담'을 제시 | 외부기관 소관은 담당 OrgUnit이 없어 `dept` 축으로 절대 안 잡힘 | `external_org`/`has_external` 축 추가 → 정확히 3건 |
| `수수료 1000원 이하 민원 목록` → 조건을 버리고 111건 전부 | 금액 조건을 읽는 축이 없음 | `fee_max_limit`/`fee_min_limit` 축 추가 |

### 후보 배제 규칙이 정답까지 버린 케이스

`미세먼지가 건강에 미치는 영향`이 실패했다. 본문에 `"미세먼지가 건강에 미치는 영향은? … 호흡기 질환, 심혈관 질환, 천식"`이 **그대로 있는데도** "확실한 답을 찾을 수 없습니다"가 나왔다.

이분법으로 좁히니 후보 1·3개면 OK, 4·5개면 NG. 본문 길이를 잘라봐도 600 NG / 900 NG / 1200 OK / 1500 NG로 **비단조**라 분량 문제가 아니었다.

원인은 `SYSTEM_PROMPT` 1번의 "업무가 다르면 제외 → 다 제외되면 모른다"였다. 비슷한 미세먼지 페이지 5개가 서로를 밀어내 정답 블록까지 버려졌다. 제외 기준을 못박아 해결:

> 1번의 제외 기준은 '담당 업무가 다른가'이지 '다른 후보와 주제가 겹치는가'가 아니다. 어떤 후보의 본문에 질문이 묻는 내용이 실제로 적혀 있으면, 비슷한 주제의 후보가 여럿 같이 왔더라도 그 후보를 근거로 답해라.

규칙을 느슨하게 푼 만큼 환각이 늘었는지 껍데기 페이지 10건을 재검사 — 억제 유지 확인.

## LLM이 프롬프트를 안 지킨 지점 (전부 규칙으로 덮음)

이번 라운드에서 **세 번** 반복됐다. 공통 패턴은 "판단이 기계적으로 되는 좁은 구간인데 LLM이 흔들린다"이다.

| 케이스 | 프롬프트로 시도한 것 | 실제 | 해결 |
|---|---|---|---|
| `무료`/`면제`의 방향 | "무료는 낼 돈이 0원이므로 pay다" 명시 + 두 번 수정 | `전자본인서명확인서발급`·`대법원 전자가족관계등록시스템`·`여권민원실 1시간 무료`가 receive로 | 무료이면서 '제공/지급/지원'이 없으면 pay로 강제 |
| 지원금 칸에 수수료 | "내는 돈은 넣지 마라" + **반례를 프롬프트에 그대로 삽입** | `인감증명발급`에 `"수수료 : 전국 동일 600원"`이 그대로 들어옴 | 수수료 표현이 있고 지원 표현이 없으면 버림 |
| 서류 역할 오인 | 프롬프트 수정 반복 | 실행마다 결과가 되돌아감 | (0820) 검증 패스 + 캐시 |

**교훈**: 프롬프트로 두 번 고쳐서 안 되면 그 구간은 코드로 판정한다. staleness·껍데기 페이지도 같은 결론이었다.

## 캐시 설계 — 기존 추출을 안 건드리는 방법

`EXTRACT_TOOL`에 필드를 추가하면 프롬프트 해시가 바뀌어 `extract_cache.json`(644건)이 통째로 무효화된다. 그러면 어렵게 안정화시킨 구비서류 추출이 전부 다시 돌고 LLM 편차로 재발할 수 있다.

그래서 **독립 스크립트 + 자체 캐시**로 필드만 덧붙였다.

```
scraping/02_extract_llm.py           EXTRACT_TOOL  → extract_cache.json        (건드리지 않음)
scraping/03_classify_fee_direction   방향 분류      → fee_direction_cache.json  (114건)
scraping/04_extract_channel_benefit  채널+지원금    → channel_benefit_cache.json (644건)
```

셋 다 재실행이 공짜고 결과가 고정된다.

```
회귀 스위트 8종      예외 0 / 실패 0
광범위 32문항        30/32
제목 검색 40표본     top1 90% / top5 100%
그래프 감사          키 중복 0 · 고아 Regulation 0 · 고아 DocumentType 0 · 임베딩 차원 이상 0
고아 노드            7 → 5   (전부 reference — 계획서·링크 모음·현황표)
```

못 맞힌 2건은 데이터 한계다 — `수원화성 관람료`는 그래프에 '관람료' 포함 문서가 **0건**, `동사무소에서 뭐 할 수 있어`는 지역 미지정이라 44개 중 어디인지 특정 불가.

## 재사용 가능한 판단

- **담을 칸이 없으면 값은 옆 칸으로 샌다.** 지원금액 칸이 없어서 수수료 칸으로 들어왔다. 프롬프트로 "넣지 마라"를 아무리 써도, 담을 곳을 안 만들면 안 고쳐진다.
- **점수 척도가 다른 두 신호는 섞어 정렬할 수 없다.** BM25와 코사인을 한 리스트에 넣으면 어휘가 항상 이긴다. 정렬 대신 "자르지 않는다"로만 쓰는 게 맞다.
- **임계값으로 진짜/가짜를 가르려다 실패하면, 잠식 폭을 제한하는 쪽이 답일 수 있다.** 분포가 겹칠 땐 어떤 임계값도 안 통한다.
- **프롬프트로 두 번 고쳐서 안 되면 코드로 판정한다.** 이번 라운드에만 세 번 반복됐다.
- **"확신 있게 과하게 답하는 것"이 "모른다"보다 나쁘다.** 조건을 조용히 버리고 111건을 반환하는 게 답을 못 하는 것보다 위험하다.
- **회귀는 실행마다 재확인해야 한다.** 미세먼지 케이스는 5회 연속 통과하다 6회째에 실패했고, 원인은 그날 바꾼 코드가 아니라 원래 취약했던 프롬프트 규칙이었다.
