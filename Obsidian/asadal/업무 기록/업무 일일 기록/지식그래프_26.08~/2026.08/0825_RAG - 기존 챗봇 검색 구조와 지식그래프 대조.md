## 개념

Chatty_Project가 지금 어떻게 학습하고 색인하고 검색하는지, 그리고 지식그래프와 어떻게 다른지 정리한 것. 지식그래프 연동([[0825_KG - 기존 챗봇 연동 구현 및 KG 버그 수정]])을 하면서 "왜 이렇게 동작하나"를 추적하다 파악한 내용이라, **소스 읽기 + 실행 로그 + 운영 DB 조회로 역추적한 것**이지 기존 챗봇 쪽 설계 문서를 본 게 아니다.

측정 대상은 수원시 홈페이지 챗봇(`newvit`, 학습 129,247건).

**한 장 요약**

```
학습   페이지/파일/이미지/영상 -> LLM 요약(memo1) + 원본 URL 을 LEARN_LIST 에 적재
색인   네 칸(제목/요약/키워드/본문)을 2~3글자 n-gram 으로 잘라 역색인 2,182만행
검색   질문을 LLM 이 가공 -> 같은 방식으로 잘라 토큰 매칭 -> 어휘 우선 순위로 정렬 -> 16건
답변   상위 청크를 프롬프트 네 칸에 나눠 넣고 LLM 1회
```

**핵심 차이 한 줄** — 기존 챗봇은 **"단어가 어디 있나"** 를 점수로 풀고, KG는 **"질문이 어떤 종류인가"** 를 먼저 가른 뒤 종류별로 다른 방법을 쓴다.

## 1. 학습 — 무엇을 저장하는가

`ASADAL_<챗봇id>_LEARN_LIST` 한 행이 학습 단위 하나다. **`content` 컬럼에 본문이 없다.**

```
subject   2026년도 수원시 환경관리원 공개경쟁채용시험 체력평가 결과 및 면접시험 실시 공고
content   https://www.suwon.go.kr/web/board/BD_board.view.do?bbsCd=1153&seq=...   <- 원본 URL
memo1     2026년 수원시 환경관리원 공개경쟁채용시험의 체력평가 결과 및 면접시험 계획을
          공고함. 관련 문의는 행정지원과 공무직운영팀(031-5191-2922)...            <- LLM 요약
chunk     1
size      330
```

`content` 평균 90자 / 최대 1,358자인 게 이 때문이다. 실제 본문은 벡터 저장소와 토큰 색인에 들어간다.

**유형별 구성**

```
post   108,200건 (84%)   보도자료·공고 등 게시판 글
image   10,211건         이미지
file     5,802건         첨부파일 (원본 5,384개 — 유일하게 다양)
video    3,097건         유튜브
url      1,836건         홈페이지 페이지
text       101건
```

**유형마다 전처리가 다르다.**

```
post   -> memo1
file   -> 파싱 후 memo1        (edu/pdf_edu.py, hwp_edu.py, xls_edu.py, doc_edu.py)
image  -> memo1 + img_describe (비전 모델이 그림 설명)
video  -> memo1 + video_summary + video_text + segments (전사 + 요약)
url    -> memo1
```

**이미지·영상까지 텍스트로 바꿔 검색 가능하게 만든다.** 학습 로직은 `edu/` 아래에 유형별로 나뉘어 있다(`url_edus/batch.py` 대량 크롤링, `single_url.py` 1건, `page_classifier.py` 페이지 유형 분류 65KB).

`chunk` 컬럼으로 분할을 추적한다 — 114,557건이 1청크, 8,809건이 2청크, 이후 급감.

## 2. 색인 — 역색인 두 표

12.9만 건을 매번 훑을 수 없으니 거꾸로 정리해둔다.

```
일반 방향   문서 -> 그 안의 단어들
색인 방향   단어 -> 그 단어가 있는 문서들     (그래서 "역색인")
```

**표 (1) `SEARCH_TOKEN_LIST` — 단어 사전 (838,267행)**

```
id      token_norm
586     청년
```

같은 단어를 수백만 번 저장하지 않으려고 번호로 대체한다.

**표 (2) `SEARCH_TOKEN_DOC_MAP` — 실제 색인 (21,820,627행)**

```
doc_id   content_type   field_name   weight   occurrence_count
55       video          subject      100.0    1
55       video          summary       40.0    1
55       video          keyword       20.0    1
```

한 줄은 "55번 문서의 제목 칸에 586번 단어(청년)가 1번, 이 자리는 100점"으로 읽는다. `'청년'` 하나가 8,076개 (문서×칸) 조합에 걸려 있다.

**표 (3)(4) 키워드 색인** — `KEYWORD_LIST` 126,521행 / `KEYWORD_DOC_MAP` 1,075,313행. 문서마다 LLM 이 키워드를 뽑아 `slot_no` 로 여러 개 붙여둔다.

### 자르는 방식 — 2~3글자 n-gram

한국어는 띄어쓰기로 못 자른다. "소파버리려면"에 띄어쓰기가 없어도 "소파"를 찾아야 한다.

```
"소파 버리려면"  ->  소파, 소파버, 파버, 파버리, 버리
```

### 가중치 — 칸 + 매칭 형태

문서 1건이 색인 121줄을 만든 실제 예:

```
subject  100   온전한 낱말        대형폐기물, 모바일, 수거, 서비스
subject   90   제목 전체 결합      수원시대형폐기물모바일수거서비스빼기
subject   70   2~3글자 조각       대형, 기물, 물모, 바일, 비스
summary  20~40
keyword  20~40
text_data   10
```

우연한 조각 겹침에는 점수를 덜 주는 구조다.

**색인 규모 (필드별 / 유형별)**

```
summary    8,136,947      post   17,936,302 (82%)
text_data  5,344,876      image   1,883,375
keyword    4,650,458      file    1,061,154
subject    3,688,346      video     566,635
                          url       358,014  (2%)
```

색인 토큰의 82%가 게시글이고 홈페이지 페이지는 2%다.

## 3. 검색 — 질문이 들어오면

```
                    질문 "소파 버리려면 스티커 얼마야"
                                |
   +----------------------------+----------------------------+
   | [1] 질문 가공   prompts/keyword_chain.yaml   LLM 1회      |
   |     대화 이력에서 빠진 주어·목적어를 채움                    |
   |     "몇 명이야?" -> "A팀 몇 명이야?"                        |
   |     조사·어미 정리, 질문 형태는 유지            1.8초 (병목) |
   +-----------------------------------------------------------+
   | [2] 키워드 역할 분리                                       |
   |     extracted_primary   질문에서 직접 뽑은 핵심어           |
   |     relation_primary    관계어                            |
   |     generated           LLM이 확장한 연관어  <- 레인이 다름  |
   +-----------------------------------------------------------+
   | [3] 질문도 같은 n-gram 으로 자름                            |
   |     "소파 버리려면" -> 소파, 소파버, 파버, 파버리, 버리       |
   +-----------------------------------------------------------+
   | [4] 매칭 — 우선순위가 정해져 있음                           |
   |                                                           |
   |     0  subject_exact         제목이 질문과 완전히 같음      |
   |     1  subject_edge_trim     제목 앞뒤 다듬고 일치          |
   |     2  subject_phrase_like   제목에 구(句)가 통째로         |
   |     3  subject_like          제목에 부분 일치              |
   |     4  map_exact             토큰 역색인 정확 매칭          |
   |     5  field_phrase_like     본문 등 다른 필드에 구 일치     |
   |     6  field_like            다른 필드 부분 일치           |
   |     9  pg_vector             임베딩 유사도   <- 가장 낮음   |
   |                                                           |
   |     정렬 키 (match_priority, -weighted_hit_score, distance)|
   +-----------------------------------------------------------+
   | [5] 점수 합산 — 필드별 가중치 곱                            |
   |     keyword_weighted_terms:                               |
   |       정책:summary  정책:keyword  정책:content             |
   |       청년:title    청년:summary  청년:keyword  청년:content|
   |       대상:title    대상:summary  대상:keyword  대상:content|
   |     keyword_weight_multiplier: 25.858                     |
   |     keyword_weighted_score:    437.072                    |
   +-----------------------------------------------------------+
   | [6] 시간 감쇠   time_weight                                |
   |     게시글은 날짜로 가중 (date_rerank_target 인 것만)        |
   |     rank_score = keyword_weighted_score x time_weight      |
   +-----------------------------------------------------------+
   | [7] 레인별 검증   _rag_filter_match_strength               |
   |     primary   레인은 추출 키워드가 전부 있어야 통과          |
   |     generated 레인은 하나만 있어도 통과 (기준이 다름)        |
   +-----------------------------------------------------------+
   | [8] vector_k=30 -> 필터 통과 16건                          |
   +----------------------------+------------------------------+
                                v
              16건 (2.0~4.9초)  각 청크에 붙는 값:
              score 437.072 / faiss_score 0.884 / hit_score 128
              matched_keywords '년대, 년대상, 대상, 정책, 청년'
              create_display_date '2025-03-28' / time_weight 1.0
```

### 벡터는 최후순위다

우선순위 표에서 `pg_vector` 가 9로 가장 뒤다. **제목이 일치하는 문서가 있으면 벡터 점수가 아무리 높아도 그게 앞선다.** 벡터는 어휘가 아무것도 못 잡았을 때 메우는 역할이다.

실측 매치 타입 분포가 그대로 보여준다.

```
search_token          9건
search_token_unified  5건
pg_vector             1건     <- 15건 중 1건
```

**"벡터 검색"이라 부르지만 실제 주 경로는 어휘 토큰 매칭이다.**

참고로 `app_local.py` 가 private RAG 백엔드를 `refactored` 로 강제하며, 이 경로는 로컬 FAISS 를 쓰지 않는다(`Config.FAISS_INDEX_DIR` 은 legacy 전용, `faiss_score` 는 계약 유지용 필드명).

```
chat/faiss_process.py -> chat/private_rag/facade.py -> ai_search/vector/service.py
    벡터        Milvus (원격)
    키워드·메타   MariaDB (원격)
```

### 재정렬

`_rerank_retriever_by_keyword_hits` 가 다시 줄 세운다. 정렬 키는 `(hit_score, base_score, -idx)` 내림차순.

```
hit_score   검색어 몇 개가 그 항목에 등장하는가 (존재 여부, 빈도 아님)
base_score  검색엔진 점수 (hit_score -> retrieval_score -> faiss_score 순으로 조회)
-idx        원래 순서 (앞선 것이 동점에서 이김)
```

첨부파일 청크는 이 재정렬에서 제외하고 앞에 고정한다 — 소스 주석에 이유가 적혀 있다.

> 첨부 chunk는 일반 검색 결과와 같은 풀에서 경쟁시키지 않는다. 키워드 재정렬에 밀려 예산에서 잘려나가면 파일 질문의 근거가 사라진다.

**KG 블록도 같은 이유로 제외 대상이다**([[0825_KG - 기존 챗봇 연동 구현 및 KG 버그 수정]] 5절).

## 4. 답변 생성 — 프롬프트 조립

`prompts/main_prompt.txt` 의 칸 구조.

```
사용자 질문:      {user_input}
질문 키워드:      {keyword_response}
최근 대화 내역:    {recent}
학습된 내용:      {retriever}          <- 청크 dict 리스트가 통째로 문자열화
학습된 내용 출처:  {source}             <- private_context + 웹검색 근거를 이어붙인 문자열
웹 검색 결과:     {websearch_result}
장기 기억 내용:    {long_term_memory}
현재 시간:        {current_time}
```

답변 규칙은 `(학습된 내용)`과 `(장기 기억 내용)`을 최우선 참고 대상으로 지목한다. `(학습된 내용 출처)`는 지목하지 않는다.

`{source}` 는 "기존 RAG 청크 본문 + 웹검색 근거"를 이어붙인 것이라 이름과 달리 **출처 목록이 아니라 근거 텍스트**다.

**LLM 은 1회만 부른다** — 검색·재정렬이 끝난 뒤 조립된 프롬프트로 스트리밍한다.

## 5. 예산 — 어디서 얼마나 잘리는가

**`{retriever}` 경로 — 일반 모델이면 제한이 없다.**

개수·글자 제한 코드가 Gemma 폴백 조건 안에만 있다. Gemma 로 넘어가면 그때만 5건/7000자, 항목당 1800자로 잘린다. 답변 청크 상한도 `5 if gemma else len(retriever)` 다.

**`{source}` 의 웹검색 자리 — 무조건 잘린다.**

```
5건 / 6000자   ->   항목당 1400자   ->   상위 3건만 답변 컨텍스트로
```

**외부 검색 결과 대기 — 기본 2초.** 초과하면 취소하고 빈 손으로 진행한다(환경변수로 조정 가능).

**챗봇 설정**은 `Config.ACCOUNT_DIR/<upload_dir>/chatbot_config.db` (로컬 SQLite)에서 읽는다. 파일이 없으면 기본값으로 새로 만든다.

```
model_name='gpt'  source_num=0  use_websearch='Y'  use_rag='Y'
vector_k=30  temperature=0.0  max_turns=3  harmful_content_filter='N'
```

`source_num=0` 이면 출처 목록 표시가 꺼진다. **운영 설정을 안 가져오면 이 기본값으로 동작한다.**

**실측 지연** (gpt-4o-mini, 수원시 챗봇)

```
질문 가공(키워드 LLM)   1.8초
private 검색           2.0 ~ 4.9초
전체 응답             13 ~ 31초
```

## 6. 지식그래프 쪽 구조 (대조용)

같은 질문이 KG 로 들어가면 이렇게 처리된다. **검색하기 전에 질문 종류를 먼저 가르는 것**이 가장 큰 차이다.

```
                        질문
                          |

   |     "영통구청장 누구야" 류                     |
   +----------+---------------------+-------------+
          걸림 |                     | 안 걸림
              v                     v
       즉시 답하고 끝        [2] 지역 감지 region.detect()
          0.01초             "장안구" -> 구 + 산하 동 목록
                                      |
   +----------------------------------+------------+
   | [3] 집계 라우터 structure.detect_civil_filter()|
   |     트리거 단어 + 15종 축                       |
   |     (대상층·분야·부서·법령·구비서류·수수료·        |
   |      지원금액·채널·외부기관 ...)                 |
   +----------+---------------------+---------------+
          걸림 |                     | 안 걸림
              v                     v

     "총 16건" = 정확한 값    "민원을 물었으면 조직 라우터 포기"
        0.03초                        |
              |            걸림 +-----+-----+ 안 걸림

              |             0.03초           |
              +-----------------+------------+
                                v

### [5] 벡터 + 어휘 경로 — 9단계

```
   5-1  지역명 제거      "권선구 세무 문의" -> "세무 문의"
        부서 임베딩에 구·동 이름이 없어 남기면 쏠림
        실측: 세무과 3등(0.72) -> 247등(0.64) 폭락

   5-2  별칭 확장        "등본" -> "등초본 발급"   (LLM 아니고 사전)

   5-3  벡터 검색        embed_query 1회 -> 전수 스캔 top 60
        1,583개 노드 전부와 코사인 계산 후 상위 60
        60인 이유: 구 단위 부서는 업무가 섞여 점수가 낮음
        실측: 팔달구 산업팀 0.688(50위권), 20이면 안 들어옴

   5-4  어휘 검색        cjk fulltext, 딱 1건 (별도 쿼리)
        name^5 가중 (표 4,000자에 우연히 든 낱말이 제목을 이겨서)
        1건인 이유: 2글자 겹침만으로 매칭됨
          "어디서" -> '어디서나민원' 9.9점
          "복지센터" -> '수원시 외국인복지센터' 12.8점
        점수를 섞지 않음. score=0 주고 "자르지 마라" 표시만

   5-5  지역 태깅        PART_OF 를 거슬러 ancestor_path
        임베딩이 아니라 그래프 관계로 소속 판정 (5-1이 가능한 이유)

   5-6  승격 3종
        별칭 승격   질문에 별칭이 그대로 -> 순위 무관하게 후보 보존
                   실측: 정답이 16위(0.739)에 머물던 것
        동 승격     지역 감지되면 그 동 자체 (전입신고는 동이 정답)
        구 sibling  같은 이름 조직을 그 구 산하에서 직접 찾음

   5-7  지역 컷        REGION_GU_CAP = 3
        (a) 법정동 관할 행정동 -> 절대 안 자름 (실측 2회 누락 사고)
        (b) 그냥 구 산하라 걸린 것 -> 상위 3개만

   5-8  동명 접기      지역을 안 물었을 때만
        조직: 최고점 하나만 + peer_count 로 "N개 구에 있음" 전달
              -> "거주지 관할 구로 가세요" 답변이 가능해짐
        민원: 이름 + 분야가 둘 다 같을 때만
              (세금'인터넷납부' vs 교통'인터넷납부'는 다른 것)

   5-9  민원 한 자리 보장
        조직만 뽑히면 최하위 조직 자리를 최상위 민원에게
        실측: 재산세팀 9개가 앞을 막아 세율표가 10위로 밀림
                                v
                        hits 최대 5건 (0.2~1.0초)
```

**후보는 60개가 아니라 "60 + 알파"다.** 어휘 1건·별칭 승격·동 승격·구 sibling 은 벡터 60위 밖에서도 들어온다. 실측:

```
소파 버리려면 스티커 얼마야
  벡터 전수스캔 상위      60개
  cjk 어휘 (별도 검색)     1개  ['대형폐기물 스티커 판매 가격표']  <- 이게 정답
  -> 지역태깅·컷·동명접기 후  5개  (LLM 이 보는 것, 7,862자)
```

**60은 "판단할 재료"지 답 후보가 아니다.** 5개만 뽑으면 정답이 50위권일 때 걸러낼 대상에 아예 안 들어온다. 그리고 전수 스캔이라 `LIMIT 5` 든 `LIMIT 60` 이든 계산량이 같다.

## 8. 혼합했을 때 전체 흐름

`/ask_kg?mode=hybrid&inject=retriever` 로 질문 하나가 들어왔을 때.

```
              /ask_kg?mode=hybrid&inject=retriever
                            |
      +---------------------+---------------------+
      |                                           |
  KG (먼저 띄움)                            기존 챗봇 전처리
      |                                     chat_id·언어·설정 (병렬)
  [1] 리더?      --걸림--> 0.01s 끝                |
  [2] 지역 감지                            [1] 질문 가공 LLM  1.8s (병목)
  [3] 집계?      --걸림--> 집합연산 0.03s    [2] 키워드 역할 분리
  [4] 조직목록?  --걸림--> 0.03s            [3] n-gram 자르기
  [5] 벡터+어휘 (9단계) 0.2~1.0s            [4] 매칭 (우선순위 0~9)
      지역명제거 -> 별칭확장                 [5] 필드별 가중 합산
      -> 전수스캔 60 -> cjk 1건             [6] 시간 감쇠
      -> 지역태깅 -> 승격3종                 [7] 레인별 검증
      -> 구컷3 -> 동명접기 -> 민원보장        [8] vector_k=30 -> 16건
  [6] 근거 블록 조립                                |
  [7] 브리지 변환 (경로별)                          |
      집계=1건통째+대표URL / 벡터=최대5건            |
      |                                           |
   0.03~1.0초                                2.0~4.9초
      +---------------------+---------------------+
                            v
                 patched vector_search
                 KG 1~5건 + 기존 챗봇 16건 = 17~21건
                            v
                 재정렬에서 KG 제외 + 선두 고정
                 (KG 3점 vs RAG 4점 -> 안 빼면 13위로 밀림)
                            v
                 예산 (일반 모델 통과 / Gemma면 5건·1800자)
                            v
                 {retriever} KG가 맨 앞인 dict 리스트
                 {source}    같은 청크들의 본문 이어붙임

**`retriever` 슬롯에 넣으면 `{source}` 에도 자동으로 실린다** — `private_context` 가 같은 청크들에서 만들어지기 때문이다. 즉 KG 내용이 프롬프트 두 칸에 다 들어간다.

**혼합의 지연은 KG 때문이 아니다.** KG 는 1초 안쪽에 끝나고 병렬이라 거의 공짜다. 25.8초는 기존 챗봇 의 질문 가공 LLM + 원격 Milvus 왕복이다.

## 9. 관측된 한계

지식그래프와 비교하며 확인된 것들이다.

**(1) "전부"를 셀 수 없다**

점수 순 상위 N개를 자르는 것이 전제다. "청년 대상 민원이 몇 건인가"에 답하려면 조건에 맞는 것을 빠짐없이 세야 하는데 구조상 불가능하다.

**(2) 표가 뭉개진다**

가격표 페이지가 `memo1` 한 문단으로 압축되며 행 데이터가 사라진다.

```
원본   1인용 소파 3,000원 / 2인용 5,000원 / 3인용 7,000원 / 카우치 6,000원
memo1  대형폐기물 배출 시 품목별 스티커를 구매해야 하며 가격은 품목에 따라 다르다
```

실측 2건 모두 "일반적으로 ~ 사이" 형태로 지어냈다.

```
"소파 버리려면 스티커 얼마야"
  -> "일반적으로 5,000원에서 10,000원 사이"      실제 3,000~20,000
"주정차 위반 과태료 얼마야"
  -> "일반적으로 4만 원에서 10만 원 사이,
      어린이 보호구역은 일반 도로의 2배인 8만 원"  실제 어린이보호구역 12~13만원
     근거 9,277자(16청크)에 '4만'·'10만' 이 0회
```

**(3) 제목만 맞고 내용은 무관한 문서가 상위로 온다**

```
subject  수원시, 대형폐기물 모바일 수거 서비스 "빼기"     <- '대형폐기물' 100점
유형     video
memo1    나쁜 버릇을 더 쉽게 버리고 원하는 것을 더 쉽게 찾는 방법에 대해 다룹니다.
```

영상 전사를 LLM 이 잘못 요약했는데, 제목 점수가 만점이라(그리고 `subject_like` 가 우선순위 3) "소파 버리려면"에 상위 후보로 올라온다. **색인은 "제목에 그 단어가 있나"를 잘 찾지만 "그 문서에 답이 실제로 적혀 있나"는 모른다.**

**(4) 오래된 게시글이 이긴다**

색인의 82%가 게시글이다. "청년 정책"을 물으면 제목에 '청년'과 '정책'이 다 든 2022년 실태조사 보도자료가 최상위로 온다.

실측: "청년기본소득 신청 기간"에 **2024~2025년 분기별 접수 일정을 그대로 나열했다.** 프롬프트에 현재 시각(2026-08-26)과 "일정은 현재 시각 기준으로 답하라"는 규칙이 있는데도 그랬다.

**(5) 단어가 겹치면 의미가 달라도 이긴다**

'청년정책팀'이라는 부서명이 제목에 있으면 인사발령 공고여도 '청년정책'으로 점수를 받는다.

```

```

지표는 규칙 기반 대리 지표이고, 오탐을 걷어낸 뒤 값이다(URL 내 숫자·만 표기·"N개" 표현 인식 추가). 자세한 경위는 [[0825_KG - 기존 챗봇 연동 구현 및 KG 버그 수정]].
