## 개념

라운드별 작업 기록(`KG - ...구현`, `...확장`)과 달리, **프로젝트 전체에 걸쳐 계속 갱신되는 상태·참고 자료**를 모아둔 계획 노트.

원래 `KG - Layer 2 계획 (민원·서류·법령·절차)`에 있던 두 절이다. 그 노트의 나머지(1차 파일럿 20페이지 실행 계획, 스키마 확정안, 페이지 수 조사)는 전부 구현으로 흡수돼 실제 코드가 정본이 됐으므로 폐기했고, 아직 살아 있는 이 두 절만 분리해 남겼다.

| RFP 항목 | 상태 | 근거 |

| 복합조건(처리부서/민원유형/필요서류) + 지식그래프 | ✅ | 집계질의 축 11종 |
| 환각 방지 — 검증된 범위 내 답변 | ✅ | 껍데기 페이지(본문이 제목뿐) 대응까지 |
| 환각 방지 — 근거자료(링크) 명시 | ✅ | `source_url` 전건 저장·답변 노출 |
| 최신 자료 우선순위 | 🟡 | `updated` 기반 3년 경과 경고까지. **검색 순위에 반영은 미착수** |
| 표·이미지 검색 | ❌ | 이미지 alt만 회수(30페이지). **첨부 PDF·표 구조 미착수** |
| RAG-챗봇 분리 / API 제공 | 🟡 | 구조적으론 분리됐으나 **실제 API 래핑 안 함** |
| 시맨틱 캐싱 | 보류 | 우선순위 낮음으로 합의 |

**실질적으로 남은 것은 3개** — 최신자료 우선순위 반영, 첨부/표 처리, API 래핑.

## 데이터 소스 조사 (미사용)

Layer 2는 결국 **전부 수원시 홈페이지 스크래핑**으로 채웠다(644건). 아래 공공데이터 API 3종은 조사만 하고 쓰지 않았다.

**안 쓴 이유**: 이 API들은 "혜택·지원사업·조례"는 커버하지만 **"인감증명 발급" 같은 일상 민원의 절차·구비서류를 다루지 않는다.** Layer 2의 핵심이 바로 그 절차·구비서류라서, 커버리지가 맞는 스크래핑을 택했다.

| 소스 | 내용 | 비고 |
|---|---|---|
| 정부24 공공서비스(혜택) API (odcloud.kr) | 수원시 혜택·지원사업 46건 | `totalCount`가 필터를 무시하는 버그 — 실제 값은 `matchCount` |
| 지자체복지서비스 API (apis.data.go.kr) | 수원시 복지서비스 21건 | 지역 필터 + 태그 제공 |
| 국가법령정보 공동활용 (open.law.go.kr) | 수원시 자치법규(조례) **868건** | `OC=test`로 승인 없이 즉시 사용 가능 |

**재활용 가치가 있는 건 세 번째다.** 현재 `Regulation` 210종은 민원 본문의 법령근거 문자열(`"도로교통법 제32조; 주차장법 제6조"`)을 파싱해 만든 것이라 **이름과 조항 번호만 있고 조문 내용이 없다.** "도로교통법 제32조가 무슨 내용인데?"에는 답할 수 없는 상태다. 조문 원문이 필요해지면 이 API가 정확히 그 자리를 채운다.

앞의 두 개는 지금 스크래핑으로 이미 덮은 영역이라 중복이다 — 다시 볼 일이 있다면 교차검증용 정도.
