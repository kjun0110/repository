# 업무 일일 기록 작성 규칙

---

## 파일명

- `MMDD_분류 - 제목.md` (예: `0827_KG - 컨텍스트 축소 기각과 답변 빈약의 원인`)
- 제목은 그날 **밝혀진 결론**이다. 한 일이 아니다
- 파일명이 제목을 대신하므로 H1은 쓰지 않는다. 메타 파일은 `_` 접두사

---

## 문서 구조

```
개념 → 요약 → 번호 절 → 검증 → 재사용 가능한 판단 → 한계 → 관련 문서
```

| 절 | 담는 것 |
|---|---|
| 개념 | 맨 위. 이 문서를 읽는 데 필요한 말을 `- **용어** — 한 줄 정의` 로 나열. 없으면 절을 두지 않는다 |
| 요약 | 그날 밝혀진 것을 한 화면 안에. 여기만 읽어도 그날이 잡혀야 한다. 직전 라운드를 `[[링크]]`로 잇는다 |
| 번호 절 | 사안 하나에 한 절. 제목에 결론을 적는다 |
| 검증 | 무엇을 몇 건 어떻게 확인했는지 |
| 재사용 가능한 판단 | 다음에 같은 상황에서 쓸 교훈 |
| 한계 | 이 결과를 인용할 때 알아야 할 것. 불릿 한 줄씩, 다시 셀 수 있게 숫자와 분모를 남긴다(`커버율 49% (112개 중 55개)`). 한 절에만 걸리는 단서는 여기가 아니라 그 절 안에 둔다 |
| 관련 문서 | 링크마다 왜 관련되는지 한 줄 |

**일일 기록은 그날 이후 고치지 않는다.** 나중에 틀린 게 드러나면 원래 문서를 손대지 말고 새 문서에 `> **정정.**`으로 적는다.

## 절 내부 흐름

```
문제 → 원인 → 검토한 안과 기각 사유 → 택한 안과 이유 → 구현 → 결과
```

각 단계는 `#####` 헤딩 한 줄로 세우고 설명을 바로 아래 줄에 붙여 쓴다. 다음 라벨 앞에서만 한 줄 띄운다.

```
##### 원인 — SYSTEM_PROMPT의 두 줄
"담당 부서 이름, 상위 소속, 담당자 연락처를 포함해서 간결하게 답해라"
"본문은 구비서류/절차/법령/수수료 줄만으로는 답할 수 없는 질문에만 근거로 사용해라"
절차 질문이라 `절차:` 줄로 답할 수 있다고 판정되어 본문 2,549자가 근거에서 빠진다.

##### 택한 안 — 소관 안내 스텁 노드
이름이 정확히 걸려 1순위로 올라오고 옆 민원을 복사할 자리가 사라진다.
```

- 절은 `##`, 라벨은 `#####`. 사이 단계는 쓰지 않는다 — 헤딩이라야 접히고 아웃라인에 뜨며, 라벨이 절 제목만큼 무거워 보이면 안 된다
- 대안을 검토하지 않았으면 그렇게 적는다. 빈칸은 검토한 것처럼 읽힌다
- 절 제목이 결론을 말하지 못할 때만 끝에 `##### 결론`을 둔다. 마지막 라벨이 이미 결론이면 두지 않는다

---

## 서식

- **표 앞에는 빈 줄을 둔다.** 붙이면 표로 파싱되지 않고 `|`가 그대로 보인다
- 코드블록은 앞 줄에 붙여도 된다. 라벨 바로 뒤에 표가 오면 표 규칙이 이긴다 — 빈 줄을 둔다
- 공백 들여쓰기는 쓰지 않는다. 4칸 이상은 코드블록이 되고 1~3칸은 무시된다

---

## 문체

- **제목·라벨은 명사형으로 끝낸다**
  `네 갈래 전부 기각`, `갈래 ① 블록 내 중복 제거 — 기각`, `이 줄기는 닫힘`
- **설명은 `~음`과 `~다`를 섞어 쓴다.** 사실을 끊어 나열할 땐 `~음`, 인과를 이을 땐 `~다`
  `REQUIRES 0개, 절차 없음. 세 프롬프트의 답이 모두 블록4의 복사다`
- `~요`·`~습니다`나 "~인 것 같다"는 쓰지 않는다
- **경과를 이야기하지 않는다.** 한 일의 순서가 아니라 확인된 사실을 적는다
  `검색 빈도로 가중하면 4.2%다` (`가중해서 재봤더니 달라졌다` 아님)
- 근거는 `파일:줄`로, 측정치는 표본 수와 함께 적는다. 1회 측정이면 1회라고 밝힌다
- 기각한 안도 남긴다. 왜 안 되는지가 다음 검토를 막는다
