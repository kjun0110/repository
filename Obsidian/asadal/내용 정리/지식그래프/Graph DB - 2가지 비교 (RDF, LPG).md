RDF/OWL이 유리한 경우
- 여러 기관·시스템이 같은 의미로 데이터를 공유/통합해야 할 때 (예: 전국 지자체가 다 같은 조직 온톨로지를 쓰고, 행안부가 그걸 다 모아서 표준적으로 통합·질의하고 싶은 경우)
- URI 기반이라 전역적으로 유일한 식별자 체계를 자연스럽게 지원 → 서로 다른 기관 데이터를 링크(Linked Data)하기 좋음
- 형식논리 기반이라 자동 추론·일관성 검증이 표준적으로 지원됨 (리즈너가 공짜로 해줌)
- 즉 "지식을 공식적으로 표현해서 남들도 재사용하게 하고 싶다"는 목적에 최적화

Property graph가 유리한 경우
- 하나의 애플리케이션/서비스 안에서 그래프를 빠르게 탐색하고 실용적으로 쓰고 싶을 때
- 엣지에도 자유롭게 property를 붙일 수 있어서(예: REPORTS_TO에 since: 2023 같은 속성) 모델링이 더 유연·직관적
- Cypher 같은 쿼리언어가 경로 탐색에 훨씬 편하고, 대부분 실무 프로젝트에서 성능도 좋음
- 근데 표준화된 전역 식별자 개념이 없어서, 다른 기관 시스템과 데이터를 자동으로 통합하긴 어려움 (그러려면 별도 매핑 작업 필요)
