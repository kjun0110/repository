### 온톨로지가 정의하는 것 4가지 (다시 정리)

지난번에 정리했던 것 그대로:

1. **클래스** — Neo4j로 치면 → **라벨**에 대응
2. **관계(Domain/Range)** — Neo4j로 치면 → **엣지 타입** + "이 타입은 어떤 라벨에서 어떤 라벨로만 가야 한다"는 **규칙**
3. **배타 관계(Disjoint)** — Neo4j로 치면 → "이 라벨 두 개는 동시에 못 붙는다"는 **규칙**
4. **개체** — Neo4j로 치면 → **실제 노드**

### 핵심: 온톨로지가 정의하는 건 "이름"이 아니라 "규칙" - 즉 100% 통하는 규칙 카테고리 같은거

라벨 자체는 그냥 문자열 이름표예요. `Actor`, `Person` 이런 건 Neo4j에서도 자유롭게 아무 문자열이나 붙일 수 있어요, 아무 검증 없이.

**온톨로지가 진짜로 하는 일은, 이 이름표들 사이에:**

- "Actor는 Person의 하위 개념이다" (계층 규칙)
- "ACTED_IN은 반드시 Actor에서 Drama로만 가야 한다" (Domain/Range 규칙)
- "Actor와 Broadcaster는 동시에 될 수 없다" (배타 규칙)

**라는 "제약/논리"를 정의하고, 그걸 강제(enforce)하는 것**이에요.

### 그래서 Neo4j로 옮길 때 뭐가 없어지는지 다시 보면

```
Protégé/OWL에서 정의한 것          Neo4j로 옮겼을 때
─────────────────────────────    ─────────────────────────────
클래스 이름 (Actor)          →    라벨 이름 (:Actor) ✅ 그대로 옮겨짐
클래스 계층 (Actor⊂Person)   →    ❌ 규칙 자체는 안 옮겨짐, 
                                    사람이 SET n:Person으로 흉내내야 함
관계 이름 (ACTED_IN)         →    엣지 타입 이름 (:ACTED_IN) ✅ 그대로 옮겨짐
Domain/Range 규칙            →    ❌ 강제 안 됨, 
                                    사후 쿼리로 검증해야 함
배타 규칙                    →    ❌ 강제 안 됨,
                                    사후 쿼리로 검증해야 함
```

### 비유로 정리하면

온톨로지는 "**단어장(라벨 이름들) + 문법책(그 단어들을 어떻게 조합해야 하는지 규칙)**"을 같이 만드는 거예요. Neo4j로 옮길 때는 **단어장(라벨/타입 이름)만 그대로 가져올 수 있고, 문법책(규칙/제약)은 못 가져와요** — 그 문법을 지킬지 안 지킬지는 사람이 짠 검증 코드가 대신 감시해야 하는 거죠.


### Domain/Range 규칙이 뭔지

**"이 관계(엣지)는 반드시 이런 타입에서 시작해서 저런 타입으로 끝나야 한다"**는 규칙이에요.

### 배타 규칙도 완전히 같은 구조

**"이 두 라벨은 절대 한 노드에 동시에 붙을 수 없다"**는 규칙이에요.
