## 개념

`suwon_ontology_opus`의 구축 작업을 Layer 0~3으로 나눠 정리한다. 숫자 순서는 "나중에 만든 것"이 아니라 **서로 다른 축**(TBox 개념 / ABox 데이터 / 신규 콘텐츠 도메인 / 검색 메커니즘)을 구분한 것이다 — 특히 Layer 3은 콘텐츠 레이어가 아니라 Layer 0/1/2 전체에 걸쳐 자동으로 적용되는 기능이라는 점이 핵심이다.

---

## 레이어별 정리 (현재 상태)

| 레이어 | 내용 | 상태 |
|---|---|---|
| Layer 0 | TBox 개념 계층 (`:Class`+`SUBCLASS_OF`, 조직 형태 분류) | 완료 |
| Layer 1 | ABox 조직 백본 (실제 조직도·직원 데이터, `PART_OF`/`TYPE_OF`) | 완료 |
| Layer 2 | 완전히 새로운 콘텐츠 도메인 (민원/서류/법령) | 파일럿 완료 (손입력 데이터, 실API 연동 전) |
| Layer 3 | 콘텐츠 레이어가 아니라 검색 메커니즘 (임베딩+벡터검색) — Layer 0/1/2 어디에나 자동 적용됨 | 이미 존재, 확장 검증 완료 |

---

## 왜 Layer 3이 "콘텐츠"가 아니라 "메커니즘"인가

Layer 0~2는 그래프에 **무엇을 채워 넣을지**의 문제고, Layer 3은 채워진 걸 **어떻게 찾아낼지**의 문제다. 그래서 Layer 2(민원/서류/법령)를 추가할 때 Layer 3(벡터 인덱스)을 새로 만들 필요가 없었다 — `instance_embedding` 인덱스가 `:Instance` 라벨 하나에 걸려있어서, 새 도메인 노드도 같은 인덱스에 자동으로 편입됐다. 이게 오늘 실측으로 검증된 부분이다.

---

## 한 눈에 요약

```
Layer 0   →  TBox (개념 계층)          →  완료
Layer 1   →  ABox (조직 백본)          →  완료
Layer 2   →  신규 콘텐츠 도메인(민원)   →  파일럿 완료, 실API 연동 전
Layer 3   →  검색 메커니즘(임베딩)      →  이미 존재, 신규 도메인에도 자동 적용 확인됨

레이어 구분 축  →  "무엇을 채우나"(0/1/2) vs "어떻게 찾나"(3)
Layer 3 특징    →  콘텐츠 레이어가 아니라 전 레이어 횡단 기능, 새 도메인 추가해도 재구축 불필요
```
